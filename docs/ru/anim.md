# `satk anim`: анимации IFP (список, JSON, запись, слияние, проверка, Blender)

[English version](../en/anim.md)

Пакет: `satk.anim` (сторона Blender: `blender/satk_blender/anim`, GPL).

## Что это

Анимации GTA:SA хранятся в пакетах IFP: `anim/ped.ifp` (ходьба, драки, машины), блоки `anim/anim.img` (бары,
спортзалы, танцы), анимации объектов в `models/gta3.img` и катсцены `anim/cuts.img`. `satk anim` читает каждый
ключевой кадр этих файлов, показывает, что внутри, превращает анимации в редактируемый JSON и обратно, добавляет
новые анимации в пакет вроде `ped.ifp`, проверяет анимацию по скелету, на котором она будет играть, и переносит
анимации в Blender и обратно: анимация IFP становится действием на оригинальном или своём педе,
импортированном через DragonFF, а действие снова становится ключевыми кадрами IFP; для MTA:SA пишется
клиентский ресурс, который грузит IFP и подменяет анимации игры. Каждый оригинальный IFP
(436 файлов, 13,7 миллиона ключевых кадров) собирается обратно байт в байт. Игра только читается; результат
пишется в `<workspace>\work\out\anim\`.

## Быстрый пример

```powershell
satk anim list ifp:ped --name walk
satk anim extract anim:ped/walk_civi --out walk.json
satk anim write walk.json --out mywalk.ifp --pack mywalk
satk anim check mywalk.ifp --sev info
satk anim merge ifp:ped mywalk.ifp --replace --out ped_mywalk.ifp
```

Что возвращается (сокращено):

## Команды

| Команда | MCP | Что делает |
|---|---|---|
| `satk anim list <ifp\|SID\|img\|folder> [--anim NAME] [--name TEXT]` | — (через `satk_op`) | анимации (кости, ключи, длительность, движение корня), кости одной анимации или IFP внутри IMG/папки |
| `satk anim extract <ifp\|SID> [NAME ...] [--all] [--out dir\|x.json\|x.ifp]` | — | анимации в JSON (по файлу на каждую или один `.json`) или в новый IFP; имена без учёта регистра, маски `*` |
| `satk anim write <json\|folder\|ifp> [--out x.ifp] [--format ANP3\|ANP2\|ANPK] [--compress keep\|yes\|no] [--pack NAME]` | — | IFP из JSON (или перекодировать/конвертировать IFP), с повторным чтением для проверки |
| `satk anim merge <base> <add ...> [--replace] [--anim NAME ...]` | — | добавить анимации в пакет вроде `ped.ifp`; совпадающие имена пропускаются или заменяются на месте |
| `satk anim check <ifp\|SID> [--anim NAME ...] [--skin model:7\|x.dff] [--loader game\|mta] [--sev info] [--fail-on error]` | — | теги и имена костей, которые движок (или `engineLoadIFP` в MTA) не свяжет, движение корня, порядок ключей, имена, сжатие |
| `satk anim mta <ifp\|SID> [--replace ped/WALK_civi=mywalk ...] [--block NAME] [--name RES]` | — | клиентский ресурс MTA (`meta.xml`, `client.lua`, сам IFP), который грузит IFP и подменяет анимации игроков и педов |
| `satk anim skeleton [model:7\|x.dff]` | — | кости скелета педа SA или модели с именем кости движка |
| `satk anim roundtrip [folder\|img\|ifp] [--via-json]` | — | декодировать и закодировать каждый IFP цели (по умолчанию папку игры) и сравнить байты |
| `satk anim to-blender <ifp\|SID> [NAME ...] [--skin model:7\|x.dff] [--verify] [--render]` | — | анимации как действия на педе в Blender: `.blend`, лист кадров, проверка туда-обратно |
| `satk anim from-blender <file.blend\|job id> [--action NAME ...] [--out x.ifp] [--fresh] [--bake]` | — | действия Blender обратно в IFP |

Цели: путь к `.ifp` (абсолютный, от текущей папки, папки игры или `<work>/out/anim`), `<img>/<entry>.ifp`
(`anim/anim.img/bar.ifp`), `ifp:<pack>` и `anim:<pack>/<name>` из индекса или просто имя пакета (`ped`). <!-- linkcheck: ignore -->

Коды `anim check`: ошибки `name_length` (имена ANP2/ANP3 длиннее 23 байт, имена костей ANPK длиннее 27),
`compression` (смешанные типы ключей или несоответствие флага сжатия ANP3), `non_finite` (NaN или бесконечность);
предупреждения `unknown_bone`, `unbound_name` (с предложенным именем), `tag_on_plain`, `duplicate_bone`,
`tag_name_conflict`, `root_motion_on_pelvis`, `duplicate_anim`, `empty`, `time_order`, `quat_norm`, `trans_limit`;
сведения `root_motion`, `no_keys`. Частичная анимация не обязана задавать ключи для каждой кости цели:
предупреждения указывают на исходные дорожки, которые не привяжутся к целевому скелету. Числовые проверки
охватывают и непривязанные дорожки. Для `model:7` оригинальный `ped.ifp` даёт ноль ошибок, 134 сообщения о движении
корня и два предупреждения об одной неиспользуемой последовательности реквизита `CAR_LjackedLHS/fam3`:
`unbound_name` и `quat_norm` (длина кватерниона отличается от единицы на 29,3%).

## Формат JSON

```json
{"satk": "anim/1", "format": "ANP3", "pack": "ped", "anims": [
{"name": "WALK_civi", "index": 262, "compressed": true, "duration": 1.1333, "bones": [
 {"name": "Root", "tag": 0, "trans": true, "keys": [
   [0.0, 0.044922, -0.018066, 0.685791, 0.72583, -0.018555, 0.0, -0.068359],
   [0.033333, 0.040283, -0.020508, 0.686523, 0.725342, -0.018555, 0.050781, -0.056641]]},
 {"name": " Pelvis", "tag": 1, "keys": [
   [0.0, -0.498291, -0.498291, -0.501221, 0.501221]]}]}]}
```

- Ключ — это `[t, qx, qy, qz, qw]` или `[t, qx, qy, qz, qw, tx, ty, tz]`: время в секундах от начала, кватернион
  поворота кости относительно родителя, смещение в метрах (у костей с `"trans": true`).
- `tag` — id кости (`satk anim skeleton`); `-1` связывает по имени кости движка (`Pelvis`, `R Forearm`).
- `"compressed": true` (по умолчанию для нового JSON) хранит поворот x4096, время x60 и смещение x1024 в знаковых
  16-битных целых: смещение должно оставаться в пределах +-32 м, положительное время — в пределах 546 с.
  Оригинальные `ped.ifp` и `anim.img` используют эту форму, а катсцены ANPK — float32. `false` записывает ключи
  с плавающей точкой.
- ANPK также поддерживает `[t, qx, qy, qz, qw, tx, ty, tz, sx, sy, sz]` с `"scale": true` и
  `"compressed": false`. Кодек сохраняет значения масштаба, хотя игра их игнорирует.
- `index` восстанавливает исходный порядок анимаций при записи нескольких извлечённых файлов; удалите или
  измените его для перестановки анимаций. `duration` и `source` — справочные. `write` сохраняет указанный формат;
  JSON без указания формата даёт ANP3.
- `*_raw`, `extra`, `kf_tail`, `name_pad` хранят исходные байтовые детали для точной обратной записи (редактор
  может их удалить). Правка `pack` или `name` имеет приоритет над сохранёнными байтами имени. Новые имена должны
  помещаться в поле формата и использовать Latin-1 без встроенных NUL. `"f32:7fc00000"` передаёт точные биты
  неконечных значений float32 из катсцен: JSON сохраняет их, хотя `check` сообщает об ошибках.

## MTA:SA

<!-- docs-smoke: skip создаёт папку ресурса; команды используют файлы из быстрого примера -->
```powershell
satk anim check mywalk.ifp --loader mta
satk anim mta mywalk.ifp --replace ped/WALK_civi=WALK_civi ped/WALK_player=WALK_civi
```

Встроенные пакеты (`ped.ifp`, `anim.img`) загружает сама игра, в MTA тоже, поэтому для них подходит
`--loader game` (по умолчанию). IFP, который ресурс грузит через `engineLoadIFP`, проходит через собственный
загрузчик MTA: тот сначала превращает имена костей без тега в id по своей таблице (нижний регистр, без пробелов:
`" Pelvis"` там работает, а в игре нет) и оставляет только свои 64 id костей — такие файлы проверяйте с
`--loader mta`. `satk anim mta` пишет `<work>/out/anim/mta/satk_anim_<block>/` с `meta.xml`, `client.lua` и самим
IFP: скрипт один раз загружает блок, вызывает `engineReplaceAnimation(ped, "ped", "WALK_civi", block, "WALK_civi")`
для каждого появившегося рядом игрока и педа (с повтором, пока блок игры ещё грузится) и `engineRestoreAnimation`
при остановке ресурса; любая анимация блока играется и напрямую через `setPedAnimation(ped, block, name)`.
Скопируйте папку в `mods/deathmatch/resources` сервера и запустите её командой `start`. Сгенерированный Lua
компилируется Lua 5.1 из MTA (это проверяется тестом).

## Blender

<!-- docs-smoke: skip нужен Blender 5.1; каждая команда запускает фоновое задание -->
```powershell
satk anim to-blender ifp:ped walk_civi run_civi --verify --render
satk anim from-blender <job-id> --out mywalk.ifp
satk anim to-blender mymod/dance.ifp dance1 --skin mymod/myped.dff
```

`to-blender` импортирует скин через DragonFF (по умолчанию `model:7`, male01; подойдёт любая модель педа или `.dff`
со своим `.txd`), создаёт по действию на каждую анимацию на его арматуре (сцена 30 кадров/с, или 60, если ключам
это нужно), сохраняет `scene.blend` в папке задания и печатает id задания. Подставьте его вместо `<job-id>` выше.
`--render` пишет лист из 4 кадров (`png`). `--verify` повторно экспортирует действия в той же сессии и сравнивает
каждую анимацию, последовательность и ключ с исходником. Для успеха нужны совпадающая структура, конечные
значения, ненулевые кватернионы и погрешности не более 0,05 градуса, 0,001 м по каждой координате смещения и
0,001 с; решение принимается до округления погрешностей. `exact` дополнительно проверяет сохранённые значения
ключей после квантования сжатых данных.

Откройте `.blend`, правьте действие, затем `from-blender <id задания или .blend>` запишет IFP. Импортированные
действия сохраняют исходный порядок анимаций и последовательностей, имена, теги и непривязанные последовательности;
переименование действия меняет его имя при экспорте. Новые каналы костей и ключи положения тоже включаются.
Новое действие (или `--fresh`) получает по последовательности на каждую анимированную кость в порядке арматуры,
с именем кости и её id; корневая кость и кости с ключами положения получают смещение. Поддерживаются кватернионы,
углы Эйлера и режим ось-угол. `--compress yes|no` переопределяет сжатие всех последовательностей, включая
сохранённые непривязанные.

`--bake` снимает вычисленную позу на каждом целом кадре диапазона действия, учитывая ограничения, обратную
кинематику, драйверы и кости скина без ключей. Для каждой кости экспортируются поворот и смещение относительно
родителя. Используйте этот режим, если движение зависит от вычислений между заданными ключами. Без него
экспорт использует времена ключей кости.

## Проверка

Измерено 2026-10-06 на доступной только для чтения копии GTA:SA 1.0 US, с Blender 5.1.1 и DragonFF `b3bd7aa`.
Все импорты и экспорты Blender выполнялись через публичный механизм заданий satk на оригинальном скине male01
(`model:7`).

| Проверка | Файлы | Анимации | Ключевые кадры | Результат |
|---|---:|---:|---:|---|
| Вся игра, обратная сборка напрямую и через JSON | 436 (287 ANP3, 149 ANPK) | — | 13 693 940 | 436/436 побайтных совпадений обоими способами |
| `ped.ifp`, импорт и экспорт Blender | 1 | 294 | 112 150 | 294/294 точных совпадений |
| `anim.img`, импорт и экспорт Blender | 133 | 1 577 | 890 817 | 1 577/1 577 точных совпадений |
| Повторное открытие `.blend`, экспорт всех действий `ped.ifp` | 1 | 294 | 112 150 | Весь IFP размером 1 433 248 байт совпадает |

Прогоны Blender дали нулевую погрешность поворота, смещения и времени после квантования в int16. Отдельная
проверка вычисленных матриц костей male01 на 916 исходных ключах `WALK_civi` дала максимальную погрешность
0,000021 градуса и 0,00000030 м (допуски: 0,05 градуса и 0,001 м). Синтетические тесты Blender охватывают
ограничения, кости без ключей, действия с углами
Эйлера и осью-углом, добавленные каналы и повторяющееся или убывающее время. Импорт своего скина из отдельного
`.dff` проверяется на копии male01.

Непривязанные последовательности и ранние дубли привязок сохраняются в метаданных действия; позу кости они
не задают. Поэтому точное сохранение ключей не означает, что каждая исходная дорожка привязывается к male01.
Обратная сборка кодеком охватывает и катсцены; приведённый прогон Blender охватывает `ped.ifp` и `anim.img`.

## Как это работает

- **Кодек.** ANP3 (SA), ANP2 и ANPK (раскладка III/VC у катсцен) читаются с каждым ключевым кадром как есть: int16
  у сжатых ключей, float32 у остальных. Байтовые детали, которые не следуют из значений (байты после NUL в имени,
  слова связей ANPK, ненулевое выравнивание, полезная нагрузка NaN), сохраняются, размеры пересчитываются, поэтому
  все 436 оригинальных IFP собираются обратно байт в байт, в том числе через JSON (`satk anim roundtrip
  --via-json`). Выравнивание секторов IMG после файла в него не входит. Сначала структуру проверяет
  `satk.formats.ifp`.
- **Кватернионы.** Поворот — это `CQuaternion` движка `(x, y, z, w)`; файлы ANPK хранят сопряжённый (загрузчик
  меняет знак x, y, z), поэтому satk переводит его при чтении и записи, и JSON одинаков для всех форматов.
- **Привязка** (`CAnimBlendAssociation::Init`): последовательность с тегом кости идёт на кость HAnim с этим id; без
  тега — на скиннованной модели на кость, чьё имя кости движка (таблица строк `gta_sa.exe`, а не имя фрейма DFF)
  совпадает без учёта регистра, на обычной модели — на фрейм с таким именем; последовательность с тегом на обычной
  модели не привязывается никогда; две последовательности на одной кости — побеждает последняя.
  `data/anim/ped_skeleton.json` хранит 32 кости, общие для всех 265 скиннованных оригинальных педов.
- **Движение корня.** Корневая кость (тег 0 или имя движка `Root` без тега) несёт перемещение анимаций ходьбы
  в своём смещении (+Y — вперёд); игра превращает его в движение педа. Побеждает последняя последовательность,
  привязанная к корню. Дорожка таза не считается корневой. Перемещение, оставленное на тазе, заставляет педа
  отпрыгивать назад при зацикливании анимации (`root_motion_on_pelvis`).
- **Blender.** Матрицы покоя костей DragonFF — это матрицы привязки скина; если `R` — покой относительно родительской
  кости, то базис позы кости равен `R^-1 * (T(t) R(q))`, а экспорт обращает это. Знаки кватернионов сохраняются
  (несколько оригинальных анимаций меняют знак между ключами; новые действия и результаты `--bake` получают
  непрерывность знака). Ключи с повторяющимся, убывающим или очень близким временем разделяются минимум на 1/50
  кадра, чтобы Blender не сливал их. Метаданные сопоставляют сдвинутые позиции с исходным временем; неизменённые
  позиции восстанавливают его при экспорте, в том числе для ключей с плавающей точкой. Перемещённый ключ использует
  отредактированное время; `--fresh` и `--bake` отключают это восстановление. Задания выполняются в фоне с
  изолированным профилем Blender от satk.

## Ограничения и известные проблемы

- Blender: только скиннованные педы (анимацию объекта обычного DFF можно перечислить, проверить и
  сконвертировать, но не наложить в Blender). Ключи без сжатия возвращаются с точностью float32, не бит в бит.
- Ключи масштаба ANPK сохраняются при обратной сборке кодеком и через JSON, но не применяются к костям и не
  экспортируются из привязанных дорожек Blender. Анимация масштаба Blender игнорируется с предупреждением.
  Неконечные значения преобразований нельзя применить к кости.
- `merge`, `write` и `mta` создают новые файлы; установка в копию игры или на сервер — на ваше усмотрение.
- Какие анимации игра проигрывает с флагом движения, решает исполняемый файл (определения групп анимаций), а не
  IFP; `root_motion` только сообщает величину перемещения.

## Интерфейс Python

```python
from satk.anim.ifp import read_ifp, write_ifp
from satk.anim.jsonio import ifp_to_json, json_to_ifp

ifp = read_ifp(blob)
walk = ifp.find("walk_civi")
doc = ifp_to_json(ifp, [walk])
assert write_ifp(json_to_ifp(doc)) == write_ifp(type(ifp)(ifp.format, ifp.pack, [walk], ifp.raw_pack))
```
