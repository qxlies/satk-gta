# Подключение ИИ-ассистента

[English version](../en/ai.md)

Пакет: `satk.mcp` (`satk mcp config --client`, `satk agent install-skill`). Сам сервер — [mcp.md](mcp.md).

## Что это

satk работает и без ИИ. Если вы пользуетесь ИИ-ассистентом, satk становится его набором инструментов: ассистент
ищет по индексу вашей игры, показывает листы текстур и кадры карты, читает дампы крэшей, проверяет мод линтером
и собирает текстурные моды — теми же операциями, что и команда `satk`. Связь — протокол MCP (Model Context
Protocol): клиент запускает `satk` локальным процессом и общается с ним через stdin/stdout.

Одна команда регистрирует satk в клиенте, ещё одна ставит skill satk (как пользоваться инструментами с толком).

## Быстрый пример

```powershell
satk mcp config --client cursor
satk mcp config --client lmstudio --groups core,index,media
```

Первая команда ничего не пишет и показывает: файл настроек клиента, запись для satk, ссылку для установки и есть ли
запись в файле (`status`: `ok`, `missing`, `differs`, `bom`). С `--write` запись попадает в файл:

<!-- docs-smoke: skip пишет настройки Cursor и папки skills пользователя -->
```powershell
satk mcp config --client cursor --write
satk agent install-skill
```

## Что уходит в облако

- Сам satk никуда ничего не отправляет: ни телеметрии, ни сети. MCP-сервер отвечает только клиенту, который его
  запустил, на этом компьютере.
- **Облачный** ассистент (Claude, ChatGPT/Codex, Cursor, Copilot, Gemini и другие) отправляет ответы satk своему
  провайдеру как часть разговора: имена, ID, координаты, пути к файлам, стеки крэшей и картинки, когда ассистент
  их открывает. Так устроен клиент, а не satk; смотрите политику данных провайдера.
- **Полностью локально:** LM Studio (или другой локальный клиент) с локальной моделью. С компьютера ничего не уходит.
- В каждой записи, которую пишет satk, стоит `OTEL_SDK_DISABLED=true`: даже если на машине установлен
  OpenTelemetry SDK, сервер satk трассировки не отправляет.

## Клиенты

| `--client` | Клиент | Для пользователя (все папки) | Для проекта (одна папка) | Своя команда |
|---|---|---|---|---|
| `claude-code` | Claude Code | `~/.claude.json` через `claude mcp add` | `<проект>/.mcp.json` | `claude mcp add` |
| `codex` | Codex: CLI, расширение IDE и приложение (общий конфиг) | `~/.codex/config.toml` (`CODEX_HOME`) | `<проект>/.codex/config.toml` (доверенные проекты) | `codex mcp add` |
| `cursor` | Cursor | `~/.cursor/mcp.json` | `<проект>/.cursor/mcp.json` | ссылка для установки |
| `windsurf` | Windsurf | `~/.codeium/windsurf/mcp_config.json` | — | — |
| `vscode` | VS Code, режим агента Copilot | `mcp.json` в пользовательской папке VS Code | `<проект>/.vscode/mcp.json` | ссылка для установки |
| `claude-desktop` | Claude Desktop | `claude_desktop_config.json` в папке данных приложения | — | — |
| `gemini` | Gemini CLI | `~/.gemini/settings.json` | `<проект>/.gemini/settings.json` | `gemini mcp add` |
| `lmstudio` | LM Studio (локальные модели) | `~/.lmstudio/mcp.json` | — | — |
| `continue` | Continue | — | `<проект>/.continue/mcpServers/satk.yaml` | — |
| `generic` | любой другой MCP-клиент | `--path ФАЙЛ` | `--path ФАЙЛ` | — |

- `--scope user` (по умолчанию, где он есть) делает satk доступным в любой открытой папке; `--scope project
  --project <папка>` — только в этой папке (например, в папке мода). Без `--project` проект — рабочее
  пространство satk.
- `--print-command` печатает только собственную команду регистрации клиента (Claude Code, Codex, Gemini CLI),
  чтобы запустить её самому. `--raw` печатает только фрагмент в формате клиента (JSON, TOML для Codex, YAML для
  Continue).
- VS Code хранит серверы под ключом `servers` (а не `mcpServers`) и ждёт `"type": "stdio"`: satk пишет и то и другое.
- Claude Desktop из Microsoft Store хранит настройки в папке пакета; satk её находит.

## Как satk правит файл настроек

- Другие серверы и настройки в файле остаются как были; для Codex файл TOML после правки разбирается заново, и
  ничего, кроме записи satk, измениться не должно.
- Прежний файл сохраняется рядом как `<файл>.satk-backup`; запись атомарная и без метки порядка байтов (BOM).
- Файл, который не разбирается (например, JSON с комментариями), никогда не перезаписывается: satk отвечает
  `BAD_PARAMS` и даёт фрагмент, чтобы вставить его руками.
- В ответе есть `diff` только записи satk, без других серверов (их ключи в вывод не попадают).
- `--check` только сравнивает и падает, если записи нет или она другая; запускайте его после обновления satk.
- Пользовательский конфиг Claude Code `~/.claude.json` — большой файл состояния, который переписывает работающий
  клиент: satk его не правит, а с `--write` запускает `claude mcp add` (и сначала `claude mcp remove`, если запись
  отличается).

## Какие инструменты получит ассистент

У сервера 25 своих инструментов и ещё `satk_ops` / `satk_op`, через которые доступна любая другая операция.
Список инструментов занимает контекст (до ~16 КБ), поэтому satk регистрирует только те группы, которые это
рабочее пространство может обслужить (`SATK_MCP_GROUPS`):

- `--groups auto` (по умолчанию): `core,index,media`, плюс `view`, если установлен вьювер, `re`, если собрана
  символьная БД, `blender`, если найден Blender, `engine`, если есть форк MTA. После установки одного из них
  запустите команду ещё раз.
- `--groups all` — все инструменты; `--groups core,index` — явный список (`core index media view re blender engine`).
- С неизвестным именем группы сервер не стартует и сообщает об ошибке (`satk doctor`, проверка `mcp_groups`,
  называет имя).

## Skill

`satk agent install-skill` копирует skill satk (`SKILL.md`: идентификаторы, инструменты, типовые сценарии, коды
ошибок) в Claude Code (`~/.claude/skills/satk/`) и Codex (`~/.agents/skills/satk/`). `--client claude|codex|all`,
`--scope project --project <папка>` — для одной папки, `--dest <папка>` — для любого другого клиента, который
читает skills, `--check` — проверить, свежие ли копии. Клиентам без skills укажите установленный `SKILL.md` в их
файле инструкций (например, `AGENTS.md`).

## Плагин Claude Code

Репозиторий satk — ещё и каталог плагинов Claude Code (`.claude-plugin/marketplace.json`). Плагин приносит skill и
MCP-сервер, который запускает `satk mcp`, поэтому команда `satk` должна быть в PATH (установка через pip/pipx или
папка переносимого пакета):

```powershell
claude plugin marketplace add qxlies/satk-gta    # или путь к своему клону satk
claude plugin install satk@satk
```

## Полностью локально с LM Studio

1. Установите LM Studio и скачайте модель, которая умеет вызывать инструменты.
2. `satk mcp config --client lmstudio --groups core,index,media --write` (короткий список инструментов подходит
   для маленького контекста).
3. В LM Studio откройте чат, включите сервер `satk` на панели интеграций и спросите:
   «Найди текстуру ws_rooftarmac1 и покажи лист».

## Если что-то не работает

| Признак | Что делать |
|---|---|
| Клиент не видит инструментов satk | перезапустите клиент (большинство читает настройки при старте); `satk mcp selftest` проверяет сам сервер |
| `status: bom` | файл начинается с метки порядка байтов (её пишет PowerShell 5.1): `--write` исправит |
| `BAD_PARAMS ... not valid JSON` | в настройках комментарии или синтаксическая ошибка: исправьте или вставьте фрагмент из ошибки руками |
| `differs` после обновления satk | `satk mcp config --client <клиент> --write` запишет новую запись (сначала бэкап) |
| `NOT_FOUND 'claude' is not on PATH` | установите Claude Code или выполните напечатанную команду там, где `claude` работает |

## Команды

| Команда | Что делает |
|---|---|
| `satk mcp config --client <клиент> [--scope user\|project] [--project ПАПКА]` | показать запись, файл и его состояние |
| `... --write` / `--check` / `--raw` / `--print-command` | записать / сверить / только фрагмент / только команда клиента |
| `... --groups auto\|all\|<список>` · `--name <имя>` · `--path ФАЙЛ` | группы инструментов, имя сервера, другой файл настроек |
| `satk mcp config [--write\|--check\|--raw]` (без `--client`) | собственный `.mcp.json` рабочего пространства satk для Claude Code (все инструменты) |
| `satk agent install-skill [--client claude\|codex\|all] [--scope ...] [--dest ПАПКА] [--check]` | поставить или проверить skill |
| `satk mcp selftest` | запустить сервер и провести настоящую MCP-сессию (список инструментов, бюджет размера, чистый вывод) |
