# `satk pack`: контейнеры контента, файлы кэша производных данных и перепись дедупликации текстур

[English version](../en/pack.md)

Пакет: `satk.pack`. Раскладка байтов: [saepak.md](saepak.md) (контейнер `.saepak`) и [dac.md](dac.md) (файлы DAC).

## Что это

Три инструмента для контента, который загружает и разделяет модифицированный движок:

- **`.saepak`** — один файл с множеством файлов DFF, TXD, COL, IFP, IPL и DAT. Адресация по содержимому (SHA-256,
  одинаковые файлы хранятся один раз), у каждого куска каждого файла есть хеш, поэтому загрузчик может скачивать и
  проверять части; при этом файл остаётся корректным архивом IMG VER2, и его читает стример движка и любой инструмент
  для IMG. `build`, `verify` и `inspect` собирают, проверяют и показывают паки из ваших файлов.
- Файлы **DAC** (кэш производных данных) хранят то, что нужно рендереру на каждую вершину и модель, а в обычных файлах
  отсутствует: нормали для геометрии с запечённым освещением, поток ночных цветов, тангенты, список источников света.
  `satk pack dac` получает их из DFF в `<workspace>/work/cache/dac/`. Только локально, не распространяются.
- **`census`** измеряет, сколько данных текселей сэкономил бы ключ разделения текстур: по каждому TXD и по всему профилю
  индекса. Его файлы — это числа и имена, полученные из игры, поэтому они лежат в `<workspace>/work/out/pack/census/` и
  никогда не попадают в git.

Входные данные только читаются; результаты пишутся в `<workspace>/work/` (или в `--out`).

## Быстрый пример

```powershell
satk pack census --limit 5
satk pack census --by txd --limit 5
```

Что возвращается (сокращённо; нужен индекс vanilla, `satk index build`):

## Как это работает

**Сборка.** Входные файлы сортируются по логическому имени (относительный путь в нижнем регистре, например
`models/car.dff`), хешируются один раз (SHA-256 файла и каждого чанка по 64 КиБ), одинаковые файлы хранятся <!-- linkcheck: ignore -->
один раз, каждый блок данных начинается с границы сектора в 2048 байт, а вокруг пишутся каталог IMG, манифест и футер.
Одни и те же входные данные и параметры дают одни и те же байты (ни времени, ни данных машины). Проверка заголовка
предупреждает о файлах, не похожих на то, что обещает расширение (`BAD_HEADER`), но не блокирует: контейнер не судит о
содержимом. Одна запись — не более 65535 секторов (чуть меньше 128 МиБ), это предел IMG. Имя для стриминга в IMG — это
имя файла, если оно влезает в поле из 23 символов, иначе `~<18 шестнадцатеричных цифр SHA-256>.<ext>`; так же
получает имя содержимое, чьё имя уже занято другим.

**Verify и inspect** читают сначала футер (последние 128 байт), затем манифест, поэтому работают и со скачанным
`.manifest` без данных; `--deep` читает каждую запись один раз.

**DAC.** `pack dac` вычисляет для каждой геометрии DFF: сглаженные нормали с учётом швов для геометрий без нормалей (или
для всех при `--normals all`), ночные цвета как готовый вершинный поток, тангенты по UV-набору 0 и источники света
2dEffect типа 0. Имя файла — ключ кэша, `SHA-256(байты источника, id рецепта, параметры)`, поэтому изменённый источник
или параметр никогда не найдёт устаревший файл. См. [dac.md](dac.md).

**Перепись.** Для каждого активного TXD профиля индекса считает текстуры и байты и группирует их по трём ключам: только
хеш базового уровня (`texel`), хеш и имя (`texel_name`) и ключ с сохранением имени
`(хеш, имя, формат, ширина, высота, число mip)` (`full`) — ключ, по которому две текстуры могут делить одну текстуру
D3D, а шейдеры мировых текстур по имени продолжают работать. Байты считаются для базового уровня (`mip0`) и для всех
уровней (`chain`, вычисляется по формату, размеру и числу уровней). Индекс хеширует только базовый уровень (и палитру);
`--exact` перечитывает файлы TXD и хеширует всю цепочку mip. Таблица показывает группы с наибольшей экономией
(`--by groups`) или TXD с наибольшим числом байт, общих с другими TXD (`--by txd`). Файлы лежат в
`<work>/out/pack/census/<profile>/`: `census.json` (сводка), `per_txd.csv`, `groups.csv`. Они детерминированы и
перезаписываются только при изменении.

### Числа vanilla

Чистая копия 1.0 US (профиль `vanilla`):

| Ключ | Различных | Уникально МиБ (базовый уровень) | Экономия | Уникально МиБ (все уровни) | Экономия |
|---|---:|---:|---:|---:|---:|
| все текстуры | 32 874 | 624,8 | | 703,8 | |
| `texel`: хеш базового уровня | 14 559 | 282,6 | 54,8 % | 303,6 | 56,9 % |
| `texel_name`: хеш + имя | 14 811 | 285,0 | 54,4 % | 306,1 | 56,5 % |
| `full`: хеш, имя, формат, размер, mip | 15 199 | 297,8 | 52,3 % | 320,1 | 54,5 % |
| `full` с `--exact` (хеш всей цепочки mip) | 15 729 | 315,2 | 49,5 % | 343,3 | 51,2 % |

- 32 874 текстуры в 3 979 TXD занимают 624,8 МиБ данных базового уровня (703,8 МиБ со всеми уровнями mip).
- Разделение только по хешу текселей оставило бы 14 559 текстур (282,6 МиБ); с учётом имени — 14 811 (285,0 МиБ).
- Дополнительные поля ключа разделения стоят только **числа уровней mip**: 388 групп с одинаковыми хешем и именем
  поставляются и с полной цепочкой (9 уровней), и с одним уровнем (12,8 МиБ базовых данных, 19,6 МиБ с цепочками).
  Больше ничто не разбивает группу (хеш, имя): формат и размер никогда не различаются.
- Хеширование всей цепочки (`--exact`) находит ещё 530 групп; во всех базовые уровни одинаковы, а один TXD хранит
  от двух до четырёх самых маленьких уровней mip пустыми, другой — заполненными (17,4 МиБ базовых данных, 23,2 МиБ с
  цепочками). Считать ли их равными, решает слой резидентности, который умеет достраивать маленькие уровни; перепись
  лишь считает их отдельно.
- TXD не может содержать две текстуры с одним именем, поэтому разделение **внутри** одного TXD ничего не экономит;
  вся экономия — от текстур, которые есть в нескольких TXD (345 групп имеют больше десяти копий, самая большая — 181).

## Ограничения и известные проблемы

- `pack build` упаковывает то, что дали; содержимое он не разбирает, поэтому не отличит сломанный DFF от целого
  (`BAD_HEADER` проверяет только первый чанк или сигнатуру).
- Быстрые хеши XXH3-128 требуют необязательного пакета `xxhash` (`--fast xxh3`); без него поля остаются нулевыми, а
  `verify` для пака с ними сообщает `FAST_SKIPPED`. SHA-256 проверяется всегда.
- Пак — контейнер, а не установщик: монтирование паков в игре и клиенте — задача движка.
- Числа переписи описывают файлы на диске. Что сэкономится во время работы, зависит от того, какие TXD загружены вместе.
- DAC читает DFF через сохраняющее все байты дерево чанков RenderWare; платформенные (native) геометрии пропускаются с
  предупреждением `NATIVE`. Нормали считаются по записям вершин, поэтому число вершин не меняется.

## Python API

```python
from satk.pack.sources import collect
from satk.pack.saepak import build_pack, verify_pack, Pack
from satk.pack.dac import derive_dff, encode_dac, decode_dac
from satk.pack.census import run_census

sources, warnings = collect(["mymod"])
report = build_pack(sources, "mymod.saepak", namespace="mymod")
with Pack.open("mymod.saepak") as pack:
    data = pack.read_name("models/car.dff")
    plan = pack.chunk_plan(pack.names[pack.name_index("models/car.dff")]["entry_index"])   # [(offset, length, sha256)]
```
