# `satk style`: оригинальный стиль SA в числах и проверки по нему

[English version](../en/style.md)

Пакет: `satk.style`.

## Что это

Чтобы «было похоже на San Andreas», нужны числа, а не прилагательные. `satk style` один раз измеряет каждую
модель оригинальной игры (треугольники, насколько мягкое сглаживание, развёртку, размер, плотность текселей,
prelight, коллизию) и отвечает, как выглядит класс моделей: седан, уличный объект 1-2 м, пешеход, оружие.
`satk asset check` сравнивает вашу модель (`.dff`, папку мода или модель игры) с её классом: фреймы и части,
числа и соглашения движка (краска на текстуре грязи, цветовые ключи фар, дамми на своей стороне).
`satk style texture` говорит, похожа ли текстура на оригинальную текстуру своей роли. Игра только читается;
кэш пишется в `<workspace>\work\style\`.

Два уровня детализации: `vanilla` (внутри измеренной полосы класса, для замен, которые должны не выделяться) и
`sa_plus` (по умолчанию для новых моделей: тот же вид с большим бюджетом треугольников там, где контур и
изгибы; эти числа — предложение до проверки в игре, и каждый ответ об этом говорит).

## Быстрый пример

```powershell
satk style profile car.sedan --tier vanilla --metrics veh.hd_tris shade.normal_bend dims.L
satk asset check model:426 --tier vanilla
satk asset anatomy model:426 --md
```

Что возвращается (сокращённо):

```json
{"ok":true,"cols":["metric","p10","p50","p90","n","lo","hi"],"rows":[["veh.hd_tris",2032,2207,2338,24,2032,2338],["shade.normal_bend",7.7012,9.9785,13.9871,24,7.7012,13.9871],["dims.L",5.4961,5.815,6.1527,24,5.4961,6.1527]],"peer_set":"car.sedan (24 vanilla models)","tier":"vanilla (measured)","exemplars":["model:466 glendale","model:442 romero","model:550 sunrise"]}
{"ok":true,"cols":["check","part","value","p10","p50","p90","verdict","hint","ref"],"rows":[],"cls":"car.sedan","verdict":"pass"}
```

Первый вызов строит кэш (около 10-20 с); следующие отвечают за доли секунды.

## Команды

| Команда | MCP | Что делает |
|---|---|---|
| `satk style profile <класс или модель> [--like SID] [--tier vanilla\|sa_plus] [--metrics ...]` | — (через `satk_op`) | p10/p50/p90 группы сравнения и полоса уровня; эталоны; опоры масштаба; `--classes` — список классов |
| `satk asset check <dff\|папка\|SID> [--like SID] [--cls auto] [--tier] [--md] [--full]` | — | структура, числа и правила движка против оригинала; `verdict` pass, review или fail |
| `satk asset anatomy <dff\|SID> [--md]` | — | дерево фреймов с позициями, части, материалы по ролям, сводка коллизии и TXD |
| `satk style texture <png\|txd\|папка\|tex:SID> [--role auto]` | — | текстура против оригинальных текстур её роли (салон, колесо, наклейка, кузов, пешеход, оружие, стена, земля, объект) |
| `satk style brief-check <brief.md> [--cls auto]` | — | формулировки в задании, ведущие к известным ошибкам («crisp», «flat colour», «never photographs», ...) |
| `satk style card <класс> [--tier] [--md]`, `satk style card --lint-preset --tier vanilla` | — | таблица Markdown по классу для руководств; конфиг линтера с бюджетами для `satk asset lint --config` |
| `satk style build [--force] [--validate] [--textures]` | — | построить кэш сразу; `--validate` меряет, сколько оригинальных моделей проходит свою полосу |

Классы: транспорт по типу (`car`, `bike`, `bmx`, `quad`, `mtruck`, `boat`, `plane`, `heli`, `trailer`, `train`)
и, для машин, по кузову (`car.sedan`, `car.coupe_muscle`, `car.sports`, `car.suv_pickup`, `car.van`, ...);
модели карты по виду и размеру (`prop@1-2m`, `building@16-32m`, `terrain`, `vegetation`, `interior_prop`,
`lod`, ...); `ped`, `weapon`, `pickup`, `upgrade`. Номер модели (`model:426`) или имя (`premier`) означает «класс
этой модели».

## Как это работает

- У каждого числа одно определение (`satk.style.registry`): `veh.hd_tris` = шасси + каждая часть `_ok` + колесо
  один раз; `shade.normal_bend` = насколько нормали вершин отклоняются от нормалей граней (0 = гранёная модель);
  `dims.L` = длина неповреждённой модели.
- Кэш лежит в `<workspace>\work\style\<профиль>-<хэш индекса>-<подпись>.json`; пересобранный индекс даёт новый.
- Полосы — совет, а не закон: значение `low`/`high` только заметно за полосой p10..p90 класса (`edge` между ними
  не считается). Ширина подобрана так, что около 9 из 10 оригинальных моделей проходят свой класс не более чем с
  одной строкой (`satk style build --validate`). Ошибки структуры и правил движка (`error`) значат, что игра
  покажет модель неправильно; с ними вердикт `fail`.
- `asset check` файла с именем оригинальной модели (`premier.dff`) сравнивает его с этой моделью (замена);
  `--like` и `--cls` задают сравнение явно; `asset.json` рядом с файлом может задать `tier` и `like`.

## Ограничения и известные проблемы

- Числа `sa_plus` — предложение; новые модели проверяйте рядом с оригиналом в превью и в игре.
- Маленькие классы (универсалы, RC-машинки) берут полосу родительского класса; ответ сообщает это в `fallback`.
- Класс модели без строки IDE и без оригинального имени угадывается (по фреймам и размеру); для точного
  сравнения задайте `--cls` или `--like`.

## Python API (если пакет используют другие)

```python
from satk.style import api
api.profile("car.sedan", "vanilla")["shade.normal_bend"]   # {'p10': 7.7, 'p50': 9.98, 'p90': 14.0, ...}
api.band("veh.hd_tris", "car", "sa_plus")                  # (3000, 4500)
api.check("mymod/premier.dff", tier="sa_plus")[0]["verdict"]
from satk.style.metrics import mesh_metrics                # канонические метрики меша, и внутри Blender
```
