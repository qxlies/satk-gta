# Каталог: офлайн-HTML для людей — поиск моделей, текстур и зон с миниатюрами

[English version](../en/catalog.md)

Пакет: `satk.catalog`.

## Что это

`satk catalog build` собирает из индекса (`satk.index`) статический сайт: одна страница
`work\out\catalog\index.html`, которая открывается двойным щелчком, без сервера и без интернета (внешних
CDN, шрифтов и скриптов нет). В нём поиск по моделям, текстурам, TXD и зонам с миниатюрами 128 px,
страницы моделей (DFF, COL, поля IDE, цепочка TXD, текстуры, места на карте), текстур («где используется»,
«те же пиксели»), TXD и зон («что там стоит»). Миниатюры берутся из кэшей `satk texture` и `satk model`
(недостающие догенерируются). Игра только читается; всё пишется в каталог под `work\out\`.

Каталог содержит текстуры игры — это локальный файл для себя, его нельзя публиковать.

## Быстрый пример

```powershell
satk catalog build --limit 60 --out catalog-demo
```

Что вернётся (сокращённо):

```json
{"ok":true,"file":"<workspace>/work/out/catalog-demo/index.html","dir":"<workspace>/work/out/catalog-demo",
 "counts":{"models":60,"textures":70,"images":64,"txds":59,"zones":384,"placements":0,"exterior":0},
 "thumbs":{"textures":{"kept":0,"written":64,"failed":0},"models":{"kept":0,"converted":59,"failed":0}},
 "format":"webp","map":true,"files":134,"mb":0.3,"changed":10,"removed":0,"seconds":3.2}
```

Полный каталог ванили — без `--limit`; откройте `file` в браузере:

<!-- docs-smoke: skip полная сборка идёт минуты, если кэш миниатюр пуст -->
```powershell
satk catalog build
```

Если браузер (или встроенная панель предпросмотра) показывает только «file missing: data/meta.js», он не
загружает соседние скрипты по `file://`. Раздайте папку локально и откройте `http://127.0.0.1:8000/`:

<!-- docs-smoke: skip запускает сервер, который продолжает работать -->
```powershell
py -3.12 -m http.server 8000 --bind 127.0.0.1 --directory <workspace>\work\out\catalog
```

## Команды

| Команда | MCP | Что делает |
|---|---|---|
| `satk catalog build [--out NAME] [--limit N] [--jobs 12] [--no-thumbs] [--fmt auto\|webp\|png] [--profile vanilla]` | — | собрать или обновить каталог; ответ: `file`, `counts`, `thumbs`, `mb`, `changed`, `timing` |

Параметры:

- `--out`: имя каталога в `work\out\` (`catalog-demo`) или путь внутри `work\`. По умолчанию `catalog`,
  для других профилей `catalog-<профиль>`, с `--limit` — `…-sample` (выборка не затирает полный каталог).
  Непустая папка без `catalog.json` не принимается: сборка удаляет файлы, которые сама не создавала бы.
- `--limit N`: только первые N моделей (по ID) и текстуры/TXD, которые они используют; зоны — все.
- `--no-thumbs`: ничего не рендерить и не конвертировать, взять готовые миниатюры (быстрая пересборка данных).
- `--fmt`: `auto` = WebP (≈2 КБ на текстуру, ≈1 КБ на модель), если Pillow умеет WebP, иначе PNG.

В браузере: строка поиска (`/` — фокус, `Esc` — очистить), фильтры `Models` / `Textures` / `TXDs` / `Zones`
и раздел IDE для моделей. Запрос ищется подстрокой в имени (у текстур — в `txd/имя`), все слова сразу;
точные совпадения выше. Число — ID модели; SID с `Enter` открывает страницу сразу: `model:411`,
`tex:bistro/vent_64`, `txd:vehicle`, `zone:gan1`, `pix:<hex>`. На карте: колесо — масштаб,
перетаскивание — сдвиг, щелчок по точке или строке таблицы — выбрать расстановку. На каждой странице —
готовые команды `satk` с кнопкой `copy`.

## Как это устроено

- **Данные** читаются через публичное API индекса (`IndexDB.query` порциями по 500 строк и
  `IndexDB.insts`): ваниль — 14 832 модели, 32 874 текстуры (14 559 уникальных картинок), 4 042 TXD,
  384 зоны, 50 935 расстановок, около 3 с.
- **Сайт:** `index.html` (CSS и JS внутри) + `data\*.js`. Браузеры не дают `fetch()` локальных файлов по
  `file://`, поэтому данные — скрипты `CAT.add("имя", {...})`. При открытии грузится только поисковый индекс
  (`meta`, `models`, `textures`, `txds`, `zones` — ≈2,5 МБ); страницы моделей (`data\m\<id>>7>.js`), <!-- linkcheck: ignore -->
  «где используется текстура» (`data\t\…`) и «что стоит в зоне» (`data\z.js`) — по запросу; миниатюры — <!-- linkcheck: ignore -->
  `loading="lazy"`, результаты дорисовываются по 120 при прокрутке.
- **Миниатюры:** текстуры — из кэша `work\cache\tex\<hh>\<pix>.png` (недостающий mip0 пишется через
  `satk.media`), уменьшаются до 128 px → `t\x\<hh>\<pix>.webp`; модели — превью `soft` 128 px из <!-- linkcheck: ignore -->
  `work\cache\model\` (`satk.model3d`, недостающие рендерятся) → `t\m\<id>>7>\<id>.webp`. <!-- linkcheck: ignore -->
  Ключи превью лежат в `catalog.json`: если хэш индекса и версия рендерера не изменились, готовые
  файлы не проверяются заново.
- **Карта** (`map.webp`, 1536 px на 6 × 6 км): суша — тайлы рельефа выше уровня моря (светлее — выше),
  огни — плотность HD-объектов; сверху точки расстановок (голубые — улица, фиолетовые — интерьеры,
  синие — LOD). Вода пока не рисуется, береговая линия приблизительная. Зона расстановки — наименьшая
  зона `info.zon`, в которую попадает точка.
- **Детерминизм:** одинаковый индекс → побайтно одинаковые файлы; файл переписывается только при изменении,
  лишние (`data\`, `t\`) удаляются. Повтор полной сборки: 13 с, `changed: 0`. <!-- linkcheck: ignore -->
- **Скорость** (ваниль, 12 процессов, кэши `texture export-all` и `model image --all` уже есть, машина
  нагружена соседними сборками): 4 мин 17 с, из них миниатюры текстур 52 с, моделей 197 с (на свободной
  машине — около 11 с); итог 29 612 файлов, 56 МБ (миниатюры текстур 30 МБ, моделей 15 МБ, данные 10 МБ).

## Ограничения и известные проблемы

- Нужен собранный индекс профиля (`INDEX_MISSING` → `satk index build`).
- Полноразмерная текстура на её странице берётся из `work\cache\tex\` по относительному пути: если каталог
  перенести в другое место, остаётся миниатюра 128 px.
- Модели без DFF (42 в ванили) и превью без видимых пикселей показываются заглушкой или пустым кадром.
- Без numpy нет фоновой карты (точки рисуются на сетке); без Pillow миниатюры — PNG.
- Интерфейс каталога — только на английском.
- Решения других проблем — в [troubleshooting.md](troubleshooting.md).

## Тесты

`tests/catalog` работают на синтетическом индексе (без файлов игры). Тесты с маркером `game`
(`tests/catalog/test_game.py`) берут настроенный `work\index\vanilla.sqlite`, если у него текущая схема
(`satk dev gate` собирает свой приватный индекс перед тестами на данных игры); если индекса нет или схема
старая, они один раз на модуль собирают приватный индекс vanilla во временной папке pytest (`satk index build`
с `SATK_PATHS_WORK` туда, около 10 с при прогретом кэше ОС) и общий индекс не трогают.

## Python-API (если другие пакеты его используют)

```python
from satk.catalog import build

env = build(limit=60, out="catalog-demo", jobs=12)   # {"file": ".../work/out/catalog-demo/index.html", ...}
```

Низкоуровневое: `satk.catalog.collect.collect(db, profile, limit)` (данные каталога),
`satk.catalog.worldmap.render_world(footprints, ext, world)` (карта), `satk.catalog.site.js(name, payload)`.
