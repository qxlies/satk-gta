# Форматы наблюдаемости: ключ времени, записи JSONL, JSON бенча, контейнеры

[English version](../en/obs-spec.md)

Версия спецификации: **1.0** (поток `sae-obs/1`, бенч `sae-bench/1`, контейнер `1.0`). Чтение, запись и проверка:
[obs.md](obs.md). Машиночитаемые части: `data/obs/*.schema.json` (JSON Schema 2020-12) и
`data/obs/sae-container-layout.json` (побайтовое описание); их печатает `satk obs schema`.

## Область и версии

Клиент sa-engine, выделенный сервер и тестовые боты сообщают о своей работе во времени. Все отчёты используют один
словарь, поэтому трассировки клиента, сервера и бота можно объединять, сравнивать и использовать в бенчмарках одним набором
инструментов. Семейство состоит из четырёх частей:

| Часть | Идентификатор | Что это |
|---|---|---|
| Ключ времени | - | четыре поля в каждой записи: `t_us`, `tick`, `sub`, `frame` |
| Поток JSONL | `sae-obs/1` | заголовок, затем по одному объекту JSON в строке: записи кадров, тиков, статистики, событий, сети, ввода, зерён, подгонок и завершающая запись |
| JSON бенча | `sae-bench/1` | один документ результата на запуск сцены, общий для бенча в игре и бенчей трассировки и сервера |
| Контейнер | `.saenet` / `.saerec` v1.0 | заголовок, чанки только на дозапись и таблица чанков вокруг тех же записей; необязательный zlib |

Данные не зависят от движка: ни один файл не называет игровых ресурсов, форматы не содержат игрового контента.

**Версии.** Идентификатор несёт старшую версию (`sae-obs/1`); несовместимые изменения получают новую старшую версию и
новый файл схемы. Совместимые изменения (новое необязательное поле, новый вид записи, новое значение открытого перечисления,
новый тип чанка без признака критичности) повышают младшую версию: поток записывает её как `minor` в заголовке, контейнер
— в своём заголовке. Читатель старшей версии 1 принимает любую младшую версию и игнорирует неизвестные поля (строгая проверка,
`--strict`, их сообщает). Читатель отказывается от другой старшей версии. Поля внутри старшей версии не переименовываются и
не меняют тип.

## Ключ времени

| Поле | Тип | Смысл |
|---|---|---|
| `t_us` | целое 0..2^63-1 | время сессии в микросекундах в области часов сервера (локальные часы, если нет соединения) |
| `tick` | u32 | тик сервера `T = t_us // dt_s_us`; 4294967295 = сетки тиков нет |
| `sub` | u32 | тик симуляции клиента `k = t_us * sub_n // dt_s_us` в режиме fixed; 4294967295 в режиме classic и в записях процесса, у которого его нет |
| `frame` | u32 | счётчик кадров клиента; 4294967295 для процесса без кадров (сервер, бот) |
| `tsrc` | необязательное перечисление | откуда `t_us`: `server` (запись на стороне сервера), `est` (оценка клиента, часы синхронизированы), `est_unlocked`, `local` (нет соединения) |

`dt_s_us` — период тика сервера в целых микросекундах (33333 для 30 Гц), `sub_n` — число тиков клиента на тик сервера
(`dt_c = dt_s / n`); оба значения лежат в заголовке потока. Ключи полностью упорядочены по `(t_us, tick, sub, frame)`.
Объединение потоков нескольких узлов — слияние в этом порядке (`satk obs merge`); оно настолько точно, насколько
выровнены часы: записи с `tsrc` равным `local` не привязаны ко времени сервера.

Правила, которые проверяет валидатор: `tick` равен `t_us // dt_s_us` или 4294967295 (всегда второе, когда `dt_s_us` равен 0);
у записи `tick` значение `sub = t_us * sub_n // dt_s_us` (её `t_us` — первая микросекунда тика: `ceil(k * dt_s_us / sub_n)`);
у любой другой записи `sub` не больше этого значения (последний завершённый тик); режим classic (`sim: classic` в
заголовке) везде имеет `sub` равный 4294967295 и не содержит записей `tick`.

## Поток JSONL `sae-obs/1`

Файл UTF-8, один объект JSON в строке, концы строк `\n` (при чтении допускаются BOM и `\r\n`). Первая запись —
заголовок, последняя — завершающая. Записи упорядочены по `t_us` для каждого узла. Файлы любого размера читаются построчно.

| `rec` | Когда пишется | Обязательные поля кроме ключа | Необязательные |
|---|---|---|---|
| `hdr` | один раз, первой (без ключа) | `schema`, `role`, `node`, `clock` | `minor`, `session`, `sim`, `pulse`, `fences`, `engine`, `producer`, `started`, `merged` |
| `frame` | в конце кадра (F7) | `frame_ms`, `ticks` | `work_ms`, `dropped_ms`, `fence_ms`, `gpu_ms`, `va_owner_mib`, `stream`, `ctr`, `gauge`, `sim`, `pulse`, `flags` |
| `tick` | после каждого тика симуляции | `tick_ms`, `dt_us` | `fence_ms`, `ctr`, `gauge` |
| `stats` | примерно раз в секунду | `frames` | `ticks`, `fences`, `game`, `mem`, `stream`, `va_owner_mib`, `gpu_ms`, `ctr`, `gauge` |
| `event` | при событии | `name` | `level`, `data` |
| `net` | на каждую строку транспорта | `dir`, `element_id`, `packet_id`, `bytes` | `peer`, `subtype`, `lane`, `seq` |
| `input` | на каждый записанный ввод | `src`, `name` | `value`, `data` |
| `seed` | на каждое зерно или параметр детерминированного режима | `name`, `value` | - |
| `snap` | на каждую подгонку объекта | `entity`, `kind` | `err_m`, `data` |
| `end` | один раз, последней (несёт ключ последней записи) | `counts` | `dropped_records`, `clean` |

Любая запись может нести `node` (в слитом потоке обязательно). Неизвестные поля допустимы (см. «Версии»).

**Заголовок.** `schema` равно `sae-obs/1`; `role` — `client`, `server`, `bot` или `tool`; `node` — идентификатор вида
`client-1`; `clock.dt_s_us` — период тика (0 = сетки нет), `clock.sub_n` — тики клиента на тик сервера, `clock.domain` —
`server` или `local`; `sim` — `classic` или `fixed`; `pulse` — `standard` или `alt` (порядок сетевого пульса); `fences`
перечисляет фенсы, о которых сообщает источник; `session` — шестнадцатеричный идентификатор, общий для файлов одной
сессии.

**`frame`.** `frame_ms` — интервал между F0 этого кадра и F0 предыдущего (то, что измеряет `timeSlice` в
`onClientPreRender`); `work_ms` — процессорное время от F0 до F7 без ожидания ограничителя; `ticks` — число тиков симуляции в
кадре (classic: 1 для симулируемого кадра, иначе 0); `dropped_ms` — симулируемое время, отброшенное защитой от спирали
смерти в этом кадре; `fence_ms` сопоставляет имени фенса (`F0`..`F7`, при необходимости с буквой подфенса: `F3b`, `F6a`)
миллисекунды в его обработчиках; `gpu_ms` сопоставляет проходу рендера миллисекунды (с запаздыванием в два кадра);
`va_owner_mib` сопоставляет владельцу бюджета занятое им адресное пространство; `stream` — `{used_mib, budget_mib}`;
`ctr` — счётчики, накопительные с начала потока и не убывающие (`sim.dropped_ms`, `timer.reentry`); `gauge` — уровни на этом кадре
(`visible_entities`); `flags` перечисляет `minimized`, `skipped_render`, `loading`, `front_end`, `cutscene`, `rebase`.
`t_us` записи кадра — время, снятое в F0.

**`tick`.** `tick_ms` — процессорное время части тика, `dt_us` — симулируемый шаг. Потоки сервера используют записи `tick`
для цикла тиков сервера (`sub` и `frame` равны 4294967295).

**`stats`.** Оконные числа `getEngineStats()`: `frames` — блок статистики кадров (ниже) за последнее окно (движок хранит 1024
кадра), `ticks` и `fences` — блоки `{n, avg_ms, p50_ms, p95_ms, p99_ms, max_ms}`, `game` — `{time_ms, timer_mode,
frame_counter, frame_counter_hz, clock_ratio}` (собственные часы SA, а не время сессии), `mem` — `{va_used_mib,
va_largest_free_mib, private_mib, working_set_mib, va_guard, cef_loaded}`.

**Блок статистики кадров.** `n`, `avg_ms`, `p50_ms`, `p95_ms`, `p99_ms`, `p999_ms`, `max_ms`, `fps_avg`, `low1_fps` (FPS по
среднему самых медленных 1 % кадров), `integer_share`, `sum_ms`, `wall_ms`, `fps_wall` и `q` — перцентили с 0-го по 100-й
(101 значение). Перцентили — точные значения по ближайшему рангу в отсортированных кадрах: `q[p] = sorted[floor(p/100 *
(n-1) + 0.5)]`. Тот же блок встречается в записях `stats` и в стадиях бенча.

**Соответствие статистике движка v1.** `getEngineStats()` клиента отображается так.

| Значение v1 | Поле |
|---|---|
| средний FPS, время кадра p50 / p95 / p99 / максимум, 1 % low | `frames.fps_avg`, `frames.p50_ms`, `frames.p95_ms`, `frames.p99_ms`, `frames.max_ms`, `frames.low1_fps` |
| `gameTimeMs`, `timerMode`, `frameCounter` и его частота | `game.time_ms`, `game.timer_mode`, `game.frame_counter`, `game.frame_counter_hz` |
| занятый VA, наибольший свободный блок, private-байты, рабочий набор, состояние защиты, CEF загружен | `mem.va_used_mib`, `mem.va_largest_free_mib`, `mem.private_mib`, `mem.working_set_mib`, `mem.va_guard`, `mem.cef_loaded` |
| использование и бюджет потоковой загрузки | `stream.used_mib`, `stream.budget_mib` |

**Завершающая запись.** `counts` содержит по числу записей каждого вида (без `hdr` и `end`). Поток без неё оборван или ещё
пишется.

### Что проверяет валидатор

`satk obs validate` выдаёт таблицу `where`, `severity`, `code`, `message`. Ошибки дают вердикт FAIL, предупреждения —
нет.

| Код | Тяжесть | Смысл |
|---|---|---|
| `JSON`, `SCHEMA` | ошибка | строка не является объектом JSON; запись нарушает свою схему |
| `HDR_FIRST`, `HDR_LATE`, `HDR_DUP`, `NODE` | ошибка | расположение заголовка; запись, у узла которой нет заголовка или узел не назван в потоке с несколькими заголовками |
| `VERSION` | ошибка / предупреждение | другая старшая версия; более новая младшая версия (предупреждение) |
| `ORDER`, `FRAME_ORDER`, `TICK_ORDER` | ошибка | `t_us` возвращается назад; номера кадров или `sub` тиков не растут |
| `KEY_TICK`, `KEY_SUB`, `KEY_FRAME` | ошибка | ключ расходится с сеткой из заголовка; запись кадра без номера кадра |
| `MODE` | ошибка | запись противоречит `sim` из заголовка (classic с `sub`, больше одного тика, запись `tick`) |
| `CTR_DECREASE` | ошибка | накопительный счётчик уменьшился |
| `END_COUNT`, `AFTER_END`, `EMPTY` | ошибка | числа в завершающей записи не совпали; запись после неё; записей нет |
| `NO_END`, `WORK`, `FENCE`, `STATS`, `BLANK` | предупреждение | нет завершающей записи; `work_ms` больше интервала кадра; фенс, которого нет в заголовке; противоречивый блок статистики; пустая строка |

## JSON бенча `sae-bench/1`

Один документ на запуск: `{schema, run, scene, label, title, started, source, request, env, key, stages, summary,
planned_stages, incomplete, error, warn}`. `source.tool` называет источник (`ingame-bench`, `obs-convert`, позже бенчи
трассировки и сервера), `source.converted_from` — схему файла, из которого выполнено преобразование. `env` говорит, что
измерялось: `role`, `sae` (true для сборки sa-engine), `build`, `preset`, `profile`, `sim`, `pulse`, `features` (какие функции
движка нашёл исполнитель), `screen`, `settings`. `key.first` и `key.last` ограничивают запуск на оси времени.

**Стадия** — одно измеряемое окно: `id`, `index`, `title`, `warmup_s`, `sample_s`, `key` (`start` и `end`), `frames`
(блок статистики кадров, обязателен), `ticks` (`n`, `per_frame_avg`, `max_per_frame`, блок `tick_ms`, `dropped_ms`),
`fences` и `gpu` (словари блоков `{n, avg_ms, p50_ms, p95_ms, p99_ms, max_ms}`), `series` (`cols` и `rows`: примерно одна строка
в секунду, `cols[0]` — `t_s`), `va` и `stream` (`start_mib`, `end_mib`, `peak_mib`, у VA ещё `growth_mib`), `clock` (`ratio`,
`frame_counter`, `frame_counter_hz`, `game_ms`, `tick_count_ms`, `timer_mode`), `ctr` и `gauge` (словари `{last, max}`),
`snap_start` и `snap_end` (снимки движка как в записи `stats`), `counts`, `probe`, `camera`, `fps_limit`, `console`, `raw`
(таблицы источника без изменений), `ext` (поля, которые преобразователь не отобразил) и `warn`.

**Сводка** объединяет стадии: `stages`, `frames`, `fps_avg`, объединённые `p50_ms` / `p95_ms` / `p99_ms` (101 перцентиль каждой
стадии с весом по числу кадров, поэтому при нескольких стадиях значения приближённые), `max_ms`, худший `low1_fps`,
`va_peak_mib`, `va_growth_mib`, `stream_peak_mib`, `clock_ratio_min` / `clock_ratio_max`, `shots_per_s`, `ticks_per_frame`,
`dropped_ms` и `pooled`, если стадий больше одной.

**Из `satk-bench/1`.** `satk obs convert` без потерь отображает файлы результатов `satk ingame bench`.

| `satk-bench/1` | `sae-bench/1` |
|---|---|
| `client` (`version`, `features`, `screen`, `sae`, `preset`, `profile`, `settings`) | `env` с `role` равным `client` |
| поля стадии `frames`, `va`, `stream`, `warn`, `counts`, `probe`, `camera`, `fps_limit`, `console`, `id`, `index`, `title`, `warmup_s`, `sample_s` | те же поля |
| `clock.tick_ms` стадии | `clock.tick_count_ms` |
| `series` стадии (строки `[t, frames, avg_ms, max_ms, va_mib, streaming_mib]`) | `series` с колонками `t_s`, `frames`, `avg_ms`, `max_ms`, `va_mib`, `stream_mib` |
| `limits_max` и `limits_last` стадии (числовые листья, через точку) | записи `gauge` вида `{last, max}` |
| `start` и `finish` стадии (таблицы engine, mem, draw) | `snap_start` и `snap_end` (нормализованные) и оригиналы в `raw` |
| любое другое поле стадии | `ext` |
| `summary` | пересчитывается той же арифметикой (на всех записанных результатах совпадает) |

Числа, которые читает `bench-compare` (`frames.p50_ms`, `p99_ms`, `va.peak_mib`, `stream.peak_mib`, `clock.ratio`), лежат
в тех же местах, поэтому те же правила сравнения дают те же вердикты для преобразованного файла.

Проверка дополняет схему: уникальные идентификаторы стадий, согласованная статистика кадров (порядок перцентилей, `q`
относительно именованных перцентилей, FPS относительно среднего), строки `series` по ширине равны `cols`, сводка
соответствует стадиям, меньше 30 кадров — предупреждение, `planned_stages` сверяется с имеющимися стадиями.

## Контейнер `.saenet` и `.saerec`

Одно семейство контейнеров: `.saenet` (вид `SNET`, трассировка транспорта) и `.saerec` (вид `SREC`, запись сессии). Содержимое
обоих — те же записи, что и в потоке JSONL; контейнер — это поток, нарезанный на чанки, при желании сжатые, с индексом.
Все целые — little-endian.

**Заголовок** (64 байта, со смещения 0).

| Смещение | Тип | Поле |
|---|---|---|
| 0 | bytes[8] | сигнатура `89 53 41 45 43 0D 0A 1A` |
| 8 | u16, u16 | версия: старшая, младшая (1, 0) |
| 12 | fourcc | вид: `SNET` или `SREC` |
| 16 | u32 | `header_size` (64; с этого смещения читатель начинает первый чанк) |
| 20 | u32 | `flags`: бит 0 FINALIZED, бит 1 COMPRESSED, бит 2 SORTED, бит 3 MERGED; остальные биты 0 |
| 24 | u64 | `index_offset` таблицы чанков (0 = не завершён) |
| 32 | u32 | `chunk_count` (верно для завершённого файла) |
| 36 | u32 | `dt_s_us`, период тика сервера (0 = неизвестен) |
| 40, 48 | i64, i64 | `t_first_us`, `t_last_us` записей (-1 = неизвестно) |
| 56 | u32 | `session_id` (0 = неизвестен) |
| 60 | u32 | CRC-32 (zlib) байтов 0..59 |

COMPRESSED — флаг сжатия: хотя бы один чанк использует кодек не 0. SORTED означает, что временные диапазоны чанков идут
в неубывающем порядке. MERGED означает несколько узлов (по одному чанку META на узел, `node` в каждой записи).

**Чанк** (заголовок 40 байт, полезные данные, нулевое выравнивание до кратности 8 байтам).

| Смещение | Тип | Поле |
|---|---|---|
| 0 | fourcc | тип |
| 4 | u8 | `codec`: 0 нет, 1 zlib (RFC 1950), 2 zstd (зарезервирован) |
| 5 | u8 | `cflags`: бит 0 CRITICAL |
| 6 | u16 | зарезервировано, 0 |
| 8 | u32, u32 | `stored_size` (байты данных как сохранены), `raw_size` (после распаковки) |
| 16, 24 | i64, i64 | `t_first_us`, `t_last_us` записей внутри (-1 = нет) |
| 32 | u32 | `rec_count` |
| 36 | u32 | CRC-32 сохранённых данных |

Типы чанков: `META` (критичный, ровно один и первый, либо по одному на узел при MERGED): запись `hdr` в JSON. `OBSJ` (критичный):
JSON Lines, записи после заголовка по порядку. `BLOB` (вспомогательный): u16 длина имени, имя UTF-8, затем произвольные байты.
Читатель пропускает неизвестный чанк, если не установлен бит CRITICAL; иначе останавливается с ошибкой. `NETB`
зарезервирован для двоичной таблицы пакетов сетевой трассировки.

**Таблица чанков** (по смещению `index_offset`, последняя в файле): `SAEX`, `entry_count` u32, `entry_size` u32 (48), 0 u32;
затем для каждого чанка u64 смещение его заголовка и копия 40-байтового заголовка чанка; затем CRC-32 всего от `SAEX` до последней
записи и `XEAS`.

**Запись.** Писатель выдаёт заголовок (flags 0), чанки по мере заполнения (так можно писать потоком, а при аварии теряется не
больше открытого чанка), а при закрытии таблицу, после чего переписывает заголовок с FINALIZED и счётчиками. **Чтение.**
Читатель использует таблицу, если она корректна, и всегда может просканировать чанки от `header_size` до `SAEX` или конца
файла; файл, который писатель не закрыл (flags 0), читается именно так, с предупреждением. Читатель обязан ограничивать
работу значениями заголовка: отказывается от чанка с `raw_size` больше своего предела (по умолчанию 256 МиБ), не
распаковывает больше `raw_size` и проверяет CRC, прежде чем доверять данным.

`satk obs validate` проверяет CRC и версию заголовка, флаги относительно чанков, таблицу относительно сканирования, CRC, размер
и кодек каждого чанка, `rec_count` и диапазон времени каждого чанка OBSJ, а затем сами записи по правилам потока
(глубокая проверка, включена по умолчанию).

## Соответствие

`satk obs sample` записывает детерминированный пример каждого вида файла. В `tests/obs/fixtures` репозитория лежат эталонный
контейнер (`golden-plain.saerec`, без сжатия, эталонный писатель воспроизводит его байт в байт) и сжатый. Писатель на другом
языке соответствует спецификации, если `satk obs validate --strict` проходит на его выводе, `satk obs unpack` возвращает его
записи, а его читатель читает оба эталонных файла.
