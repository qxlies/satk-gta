# Контейнер `.saepak`: раскладка байтов, формат 1.0

[English version](../en/saepak.md)

Пакет: `satk.pack` (`satk pack build`, `verify`, `inspect`; см. [pack.md](pack.md)). Таблицы на этой странице
печатаются из кода (`satk.pack.layout`), и тест их сверяет, поэтому они не могут разойтись с кодом.

## Что это

`.saepak` хранит игровые файлы (DFF, TXD, COL, IFP, IPL, DAT) так, чтобы их можно было монтировать, скачивать по частям
и проверять. Цели:

- **адресация по содержимому**: каждое различное содержимое хранится один раз и называется своим SHA-256; имя — отдельная
  маленькая запись, которая указывает на содержимое;
- **совместимость с IMG**: файл начинается со стандартного каталога IMG VER2, и каждый блок данных начинается с границы
  сектора в 2048 байт, поэтому стример движка и инструменты IMG читают его без изменений; всё лишнее лежит после данных;
- **чанки**: у каждого содержимого есть SHA-256 на каждый чанк (по умолчанию 64 КиБ), поэтому загрузчик может брать
  диапазоны байт и проверять каждый кусок, а повреждённая загрузка чинится по чанкам;
- **версии и расширяемость**: старшая и младшая версии, размеры заголовка и таблиц в самом файле, зарезервированные поля,
  равные нулю, и поля быстрого хеша (XXH3-128), зарезервированные в каждой записи;
- **детерминизм**: одни и те же входные данные и параметры дают одни и те же байты.

Все целые числа — little-endian. Колонки «Смещение» ниже — смещения в байтах внутри записи.

## Раскладка файла

```
offset 0                  каталог IMG VER2: "VER2", u32 count, count записей по 32 байта, добито нулями до сектора
data_offset               данные: каждое различное содержимое с границы сектора, добито нулями до целых секторов
manifest_offset           блок манифеста (кратно сектору): заголовок, таблицы содержимого, имён, чанков, строки
pack_size - 128           футер (128 байт)
```

Читатель начинает с конца: последние 128 байт — футер, который указывает на блок манифеста (HTTP-диапазон «суффикс» в
128 байт, затем один диапазон манифеста), так что данные не трогаются, пока не понадобится содержимое.
`<pack>.manifest` — копия только с манифестом: блок манифеста и следом футер (`manifest_size + 128` байт). Смещения в нём —
смещения в полном паке; читатель отличает один файл от другого по размеру (`pack_size` или `manifest_size + 128`).

### Каталог IMG

Первые секторы. Число записей — число различных имён для стриминга (`dir_count`), каждая запись:

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | u32 | `offset_sectors` | смещение данных в секторах по 2048 байт |
| 4 | u16 | `stream_sectors` | размер данных в секторах (размер для стриминга движка) |
| 6 | u16 | `archive_sectors` | всегда 0; тогда движок берёт stream_sectors |
| 8 | u8[24] | `name` | имя для стриминга, добито нулями, не более 23 символов |

Два имени с одним содержимым указывают на одни данные (два слота каталога с одним смещением) или делят один слот, если
их имена для стриминга равны. Записи отсортированы по имени для стриминга. `archive_sectors` равно 0 (движок берёт
`stream_sectors`). Одно содержимое — не более 65535 секторов (134 215 680 байт), предел 16-битного поля размера. Весь пак монтируется как
один IMG и остаётся меньше 4 ГиБ (`build` отказывает при большем размере: разделите входные данные).

### Данные

Содержимое в порядке младшего логического имени; каждое начинается с кратного 2048 смещения, за ним нулевые байты до
следующего сектора. `data_size` — длина области; `data_offset + data_size == manifest_offset`.

### Футер

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | u8[8] | `magic` | ASCII SAEPAKFT |
| 8 | u16 | `major` | старшая версия формата (1); читатель отвергает большую |
| 10 | u16 | `minor` | младшая версия формата (0); только дополнения |
| 12 | u32 | `flags` | 0 |
| 16 | u64 | `manifest_offset` | абсолютное смещение блока манифеста в полном паке (кратно сектору) |
| 24 | u64 | `manifest_size` | размер блока манифеста в байтах (кратен 8) |
| 32 | u64 | `pack_size` | размер полного файла пака; файл только с манифестом занимает manifest_size + 128 байт |
| 40 | u8[32] | `manifest_sha256` | SHA-256 блока манифеста |
| 72 | u8[16] | `manifest_fast` | быстрый хеш блока манифеста (fast_algo заголовка); ноль при fast_algo 0 |
| 88 | u32 | `crc32` | CRC-32 (zlib) байт футера 0..87 |
| 92 | u8[36] | `reserved` | ноль |

Читатель проверяет сигнатуру, CRC, старшую версию (большая отвергается), затем читает `manifest_size` байт со смещения
`manifest_offset` (или с `размер файла - 128 - manifest_size` в файле только с манифестом) и проверяет их SHA-256.

### Заголовок манифеста

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | u8[8] | `magic` | ASCII SAEMANIF |
| 8 | u16 | `major` | старшая версия формата (1) |
| 10 | u16 | `minor` | младшая версия формата (0) |
| 12 | u32 | `header_size` | 192; следующая младшая версия может увеличить заголовок, таблицы начинаются по смещениям ниже |
| 16 | u32 | `flags` | бит 0: файл начинается с каталога IMG VER2 (в 1.0 всегда установлен) |
| 20 | u32 | `sector_size` | 2048 |
| 24 | u32 | `chunk_size` | байт в хеш-чанке: степень двойки от 2048 до 64 МиБ (по умолчанию 65536) |
| 28 | u32 | `fast_algo` | 0 = поля быстрого хеша нулевые, 1 = XXH3-128, каноническая запись (big-endian) |
| 32 | u32 | `entry_count` | записей в таблице содержимого (различное содержимое) |
| 36 | u32 | `name_count` | записей в таблице имён (логические имена) |
| 40 | u32 | `dir_count` | записей в каталоге IMG в начале файла (различные имена стриминга) |
| 44 | u32 | `chunk_count` | записей в таблице чанков |
| 48 | u64 | `entries_off` | смещение таблицы содержимого от начала манифеста |
| 56 | u64 | `names_off` | смещение таблицы имён от начала манифеста |
| 64 | u64 | `chunks_off` | смещение таблицы чанков от начала манифеста |
| 72 | u64 | `strings_off` | смещение области строк от начала манифеста |
| 80 | u64 | `strings_size` | размер области строк в байтах |
| 88 | u64 | `data_offset` | абсолютное смещение первого байта данных (конец секторов каталога IMG) |
| 96 | u64 | `data_size` | байт в области данных (кратно 2048) |
| 104 | u8[32] | `pack_id` | идентичность SHA-256 для пространства имён и отображения логическое имя -> содержимое (см. спецификацию) |
| 136 | i32 | `priority` | приоритет монтирования: больший побеждает меньший при том же режиме |
| 140 | u16 | `mount_mode` | 0 overlay (перекрывает одноимённые записи нижних слоёв), 1 addon (только новые имена), 2 cache (образ кэша с адресацией по содержимому) |
| 142 | u16 | `residency_flags` | бит 0: дедупликация текстур разрешена; бит 1: только локально, не распространять |
| 144 | u32 | `namespace_off` | смещение строки пространства имён логических имён |
| 148 | u32 | `namespace_len` | длина строки в байтах |
| 152 | u32 | `title_off` | смещение строки с названием для человека (может быть пустой) |
| 156 | u32 | `title_len` | длина строки в байтах |
| 160 | u32 | `mount_name_off` | смещение строки с предлагаемым именем IMG при монтировании (может быть пустой) |
| 164 | u32 | `mount_name_len` | длина строки в байтах |
| 168 | u64 | `reserved1` | ноль |
| 176 | u64 | `reserved2` | ноль |
| 184 | u64 | `reserved3` | ноль |

За заголовком идут таблицы в таком порядке, каждая выровнена на 8 байт и адресуется смещениями из заголовка:
содержимое, имена, чанки, строки. Блок добит нулями до кратного 8 числа байт.

### Таблица содержимого (различные содержимые)

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | u8[32] | `sha256` | SHA-256 содержимого (адрес содержимого) |
| 32 | u8[16] | `fast` | быстрый хеш содержимого (fast_algo заголовка); ноль при fast_algo 0 |
| 48 | u64 | `offset` | абсолютное смещение данных (кратно сектору) |
| 56 | u64 | `size` | размер содержимого в байтах (1 .. 65535 секторов) |
| 64 | u32 | `first_chunk` | индекс первой записи в таблице чанков |
| 68 | u32 | `chunk_count` | число записей чанков: ceil(size / chunk_size) |
| 72 | u8 | `kind` | 0 прочее, 1 dff, 2 txd, 3 col, 4 ifp, 5 ipl, 6 dat |
| 73 | u8 | `flags` | 0 |
| 74 | u16 | `reserved1` | ноль |
| 76 | u32 | `stream_sectors` | ceil(size / 2048) |
| 80 | u32 | `rw_version` | версия RenderWare первого чанка (например 0x36003), 0 если содержимое не RW |
| 84 | u32 | `reserved2` | ноль |
| 88 | u64 | `reserved3` | ноль |

Записи отсортированы по младшему логическому имени и уложены подряд в этом порядке; верификатор сообщает о промежутке
между данными (`GAP`) и о пересечении (`OVERLAP`).
`first_chunk` записи *i+1* равен `first_chunk + chunk_count` записи *i*: записи покрывают таблицу чанков по порядку.

### Таблица имён (логические имена)

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | u32 | `entry_index` | индекс в таблице содержимого |
| 4 | u32 | `dir_index` | индекс слота каталога IMG, через который стримится это имя |
| 8 | u32 | `logical_off` | смещение строки логического имени |
| 12 | u32 | `logical_len` | длина строки в байтах |
| 16 | u64 | `asset_id` | зарезервировано под 64-битный AssetId реестра; в 1.0 равно 0 |
| 24 | u32 | `flags` | бит 0: имя стриминга получено из хеша содержимого |
| 28 | u32 | `reserved1` | ноль |
| 32 | u64 | `reserved2` | ноль |

Имена отсортированы по байтам UTF-8 логического имени и уникальны. Логическое имя — относительный путь в нижнем регистре с
прямыми слэшами, до 240 байт, без пустых компонентов, `.` и `..`, без `:`, оканчивающийся на `.dff .txd .col .ifp .ipl
.dat`. Это ключ, который реестр и таблица монтирования используют вместе с пространством имён пака; из них выводится id
ассета (под него зарезервировано поле `asset_id`).

### Таблица чанков

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | u8[32] | `sha256` | SHA-256 байт чанка (последний чанк записи короче) |
| 32 | u8[16] | `fast` | быстрый хеш чанка (fast_algo заголовка); ноль при fast_algo 0 |

У записи из `size` байт `ceil(size / chunk_size)` записей чанков; чанк *k* покрывает байты содержимого
`[k * chunk_size, min(size, (k + 1) * chunk_size))`, то есть абсолютный диапазон `[offset + k * chunk_size, ...)`. У
содержимого не больше одного чанка одна запись, и её хеш равен хешу записи. Размер чанка — степень двойки от 2048 до
64 МиБ (по умолчанию 65536), поэтому чанк всегда начинается на границе сектора.

### Строки

UTF-8, без разделителей и терминаторов; каждая строка адресуется парой `(смещение, длина)` из заголовка или записи имени
относительно `strings_off`. В области лежат пространство имён, название, предлагаемое имя при монтировании и все
логические имена. Равные строки хранятся один раз; пустая строка — `(0, 0)`.

## Имена, идентичность и монтирование

**Имена для стриминга.** *Имя для стриминга* логического имени — то, что видят каталог IMG и движок: имя файла из пути,
если оно не длиннее 23 символов и состоит из `a-z 0-9 _ - .` (не начинается с `.` или `-`) с трёхбуквенным расширением; иначе
`~<первые 18 шестнадцатеричных цифр SHA-256 содержимого>.<ext>` (ровно 23 символа). Если два разных содержимого хотят
одно имя файла, первое в порядке логических имён его сохраняет, остальные получают производное имя; бит 0 флагов записи
имени отмечает производное имя. Верификатор проверяет, что имя каждого слота объясняется логическим именем.

**Pack id.** `pack_id` — `SHA-256` от байт `SAEPACK1` + `0x0A`, пространства имён и `0x0A`, затем для каждого имени в
порядке байт UTF-8: логическое имя, нулевой байт, 32 байта SHA-256 содержимого и `0x0A`. Он называет, *что отображает
пак*: не меняется от размера чанка, метаданных монтирования и раскладки, а от имени, содержимого или пространства имён
меняется.

**Метаданные монтирования** (заголовок): `namespace`, `title`, `mount_name` (имя IMG при монтировании), `priority`,
`mount_mode` и `residency_flags`. Паки `overlay` перекрывают одноимённые записи нижних слоёв (побеждает больший
приоритет), паки `addon` только добавляют имена (имя, которое уже есть ниже, — конфликт для слоя монтирования), `cache` —
образ кэша с адресацией по содержимому. Бит 0 `residency_flags` разрешает слою резидентности дедупликацию текстур TXD пака;
бит 1 помечает производное или приватное содержимое, которое нельзя распространять (пак с DAC или кэш).

## Хеши

SHA-256 есть всегда и является источником истины. Поля `fast` (16 байт в каждой записи, чанке и футере) хранят
каноническую (big-endian) запись XXH3-128 при `fast_algo` 1 и нули при 0; читатель, который не умеет считать XXH3, их
пропускает и сообщает об этом (`FAST_SKIPPED`). Писатель заполняет их только по запросу (`--fast xxh3`, нужен пакет
`xxhash`), поэтому результат по умолчанию не зависит от необязательного пакета.

## Правила совместимости

- Читатель принимает любой файл со знакомой **старшей** версией и игнорирует незнакомые дополнения **младшей**: новые
  поля появляются только в зарезервированном месте или после таблиц, а `header_size` говорит, где кончается больший
  заголовок.
- Зарезервированные поля пишутся нулями; верификатор предупреждает, если это не так (`RESERVED`).
- Читатель обязан считать каждое смещение и каждое число недоверенными: сверять с файлом и размером манифеста до
  использования (эталонный читатель так и делает и отвергает манифест, чьи таблицы в него не помещаются).
- Неизвестные значения `kind` и режимов монтирования не ошибки; они показываются как есть.

## Проверка

`satk pack verify` сообщает такие коды (E — ошибка, W — предупреждение, I — информация):

| Код | Уровень | Значение |
|---|---|---|
| `UNREADABLE` | E | файл нельзя открыть или прочитать |
| `BAD_MAGIC` | E | в конце файла нет сигнатуры футера (не пак, обрезан или дописаны лишние байты) |
| `FOOTER_CRC` | E | CRC футера не совпадает |
| `BAD_VERSION` | E | незнакомая старшая версия |
| `SIZE_MISMATCH` | E | размер файла не равен ни `pack_size`, ни `manifest_size + 128` |
| `MANIFEST_RANGE` | E | манифест не выровнен, смещён или его размер неверен; область данных не кончается на нём |
| `MANIFEST_HASH` | E | SHA-256 манифеста отличается от футера |
| `MANIFEST_FORMAT` | E | таблица, строка или поле заголовка не помещаются в манифест |
| `NAME_INVALID`, `NAME_DUP`, `NAME_ENTRY`, `NAME_DIR` | E | неверное, повторяющееся или висячее логическое имя, индекс записи или слота каталога |
| `NAME_ORDER`, `KIND_MISMATCH` | W | имена не отсортированы; расширение и вид записи расходятся |
| `ENTRY_SIZE`, `ENTRY_RANGE`, `ALIGN`, `OVERLAP`, `ENTRY_DUP` | E | неверный размер или число секторов, данные вне области, невыровненные, пересекающиеся или повторяющиеся содержимые |
| `CHUNK_RANGE` | E | записи чанков не покрывают таблицу чанков или не равны `ceil(size / chunk_size)` |
| `PACK_ID` | E | `pack_id` не соответствует пространству имён и отображению имя -> содержимое |
| `DIR_MISMATCH`, `STREAM_NAME`, `STREAM_NAME_DUP` | E | каталог IMG расходится с манифестом, имя слота не объясняется логическим именем, повтор имён слотов |
| `DIR_ORPHAN`, `GAP`, `PADDING`, `RESERVED`, `TOO_LARGE` | W | неиспользуемый слот, неиспользуемые байты между данными, ненулевое выравнивание, ненулевые зарезервированные поля, файл от 4 ГиБ |
| `ENTRY_HASH`, `CHUNK_HASH`, `FAST_HASH` | E | (deep) содержимое, чанк или быстрый хеш отличаются от манифеста |
| `FAST_SKIPPED`, `MANIFEST_ONLY` | I | XXH3 не проверен (нет пакета); файл только с манифестом, данные не проверены |
