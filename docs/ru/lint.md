# `satk asset lint` — линтер ассетов

[English version](../en/lint.md)

Пакет: `satk.lint`. Правила — данные: `data/lint_rules.json`.

## Что это

Проверка модов и ванили до запуска игры: DFF (структура, лимиты, UV, prelight, нормали, данные вершин,
бюджеты), TXD (платформа, формат, степени двойки, блоки DXT, цепочка мипов, имена), COL (имя ≤ 21 и равно
модели, вершины в ±256 м, боксы без вращения, флаги, границы, поверхности, освещённость граней), IDE (длины
имён, диапазон ID, дальность прорисовки, дубли) и связка IDE ↔ DFF/TXD ↔ COL по именам. Сверх формата линтер
проверяет то, чего игра ждёт от машин, педов и оружия: фары, краску и грязь, отблеск окружения, фреймы, размер
колеса, теневой меш, части повреждений, скин, вспышку выстрела и плоское затенение. Каждое правило ссылается на
источник (`gta-reversed` файл:строка, plugin-sdk, замер на ванильной игре), многие называют вылет, от которого
защищают. Линтер только читает файлы; пишет лишь по `--save` — в `work\out\lint\` (создаётся при первом
сохранении) — и кэширует доли правил на ванили для `--baseline` в `work\cache\lint\`. <!-- linkcheck: ignore -->

## Быстрый пример

```powershell
satk asset lint-rules --rule veh --preset sa_plus
satk asset lint models/gta3.img/infernus.dff
satk asset lint model:17613 --sev info --limit 5
satk asset lint data/maps/generic/dynamic2.ide
```

Что вернётся (сокращённо, последняя команда — настоящая ошибка в данных игры):

```json
{"ok":true,"cols":["rule","sev","file","msg"],
 "rows":[["ide.draw_min","error","data/maps/generic/dynamic2.ide","line 164: model 1489 'DYN_SALE_POST': draw distance 1 < 4, the game re-reads the line in the old mesh-count form"]],
 "n":1,"total":1,"summary":{"fatal":0,"error":1,"warn":0,"info":0},"files":1,"by_rule":{"ide.draw_min":1}}
```

Машина, сделанная ИИ-агентом (бенчмарк «Тесла» как замена `premier`), с уровнем детализации по умолчанию:
`satk asset lint mymod --preset sa_plus --baseline vanilla` отвечает `dff.flat_shading` (изгиб нормалей 0,81°,
у ванильных машин 7,2–10,9°), `veh.paint_dirt` (кузов на `vehiclegeneric256` — никогда не пачкается),
`veh.env_uv2`, `veh.dummy_side` (`ped_arm` при x = +0,81), `veh.dam_ratio` (части `_dam` — 0,44 от `_ok`) и
`dff.vert_sharing`; у каждой строки есть `vanilla_rate`, а в `hints` — как исправить. У ванильного `premier`
ни одного из этих правил нет.

## Команды

| Команда | MCP | Что делает |
|---|---|---|
| `satk asset lint TARGET [--sev info\|warn\|error\|fatal] [--rule P …] [--preset game\|strict\|vanilla\|sa_plus] [--baseline vanilla] [--baseline-rate R] [--like SID] [--config F] [--no-index] [--fail-on S] [--save] [--profile P] [--limit N] [--cursor C]` | — (через `satk_op`) | таблица `rule/sev/file/msg` (с `--baseline` ещё `vanilla_rate`), `summary` по всем находкам, `hints` (как исправить правила со страницы), `suppressed` (что убрали `--baseline`/`--like`) |
| `satk asset lint-rules [--rule P …] [--preset P] [--config F] [--ru] [--ref] [--limit N]` | — | правила: id, серьёзность, параметры, что проверяет; `--ref` добавляет источник, исправление и вылет или дефект, от которого правило защищает |

`TARGET` — одно из:

- файл `.dff .txd .col .ide`, IMG-архив (все DFF/TXD/COL внутри), запись `<img>/<entry>`;
- папка мода (рекурсивно, IMG внутри раскрываются). Корень игры (есть `data/gta.dat`) проверяется так, как его
  грузит игра: только IDE из `data/default.dat` и `data/gta.dat`, отдельные `.col` — только из `COLFILE`;
- SID: `model:411` (DFF, цепочка TXD и COL модели), `dff:`, `txd:`, `col:` (одна модель коллизии), `file:`,
  `ide:`.

Относительный путь ищется от текущей папки, затем от корня профиля (без учёта регистра). Имена, которых нет в цели
(мод использует ванильный TXD или добавляет коллизию ванильной модели), ищутся в индексе профиля; `--no-index`
это отключает. SID-цели всегда требуют индекс (`INDEX_MISSING` → `satk index build`). Замена (`premier.dff` без
строки IDE) получает класс, тип машины и размер колеса ванильной модели из индекса.

Серьёзность: `fatal` — игра падает или не читает файл; `error` — грузится, но неправильно (нет коллизии, мусор
в текстуре, невидимая модель); `warn` — работает, но нарушает бюджет или соглашение; `info` — совет.
`--fail-on error` превращает находки этого уровня и выше в ошибку `CHECK_FAILED` (код выхода 1) — для скриптов
и CI; по умолчанию `never` — всегда `ok`.

Чтобы проверить мод для Mod Loader целиком (конфликты ID, файлы, которые Mod Loader пропустит, выпавшие записи
игры), есть `satk mod check` — он добавляет эти находки линтера: см. [modinspect.md](modinspect.md).

## Пресеты и уровни детализации

| Пресет | Для чего | Бюджеты |
|---|---|---|
| `game` (по умолчанию) | любые файлы; откалиброван на ванили (0 fatal) | щедрые пределы |
| `strict` | новый контент, исследование 22 | p90 ванили по классу; машины — по `veh.hd_tris` (p90 по типу), весь файл только с потолком |
| `vanilla` | уровень детализации `vanilla`: новый контент, который должен незаметно встать рядом с ванилью | p98 ванили по классу; максимумы ванили по частям машины |
| `sa_plus` | уровень детализации `sa_plus`, по умолчанию для новых ассетов (числа — предложение до проверки в игре) | `vanilla` плюс бюджеты выше там, где живут силуэт и кривизна: `veh.hd_tris` машины до 5 000, кузов 3 600, колесо 480, модели карты — 2× p90 класса |

Мипмапы во всех пресетах учитывают класс: у ванильных текстур машин, педов и оружия их нет (0 из 996), поэтому
`txd.mips_missing` для TXD этих классов — лишь `info`; класс TXD — класс использующих его моделей. Свои пороги —
в файл `--config my.json`:
`{"rules": {"txd.size_max": {"params": {"max": 512}}, "col.empty": {"enabled": false}, "txd.pow2": {"class_sev": {"cars": "error"}}}}`.

## Правила для машин, педов и оружия

| Правило | Что проверяет | От чего защищает |
|---|---|---|
| `veh.frames` | фреймы, которые есть у каждой ванильной машины этого типа (дамми колёс, кузов, сиденья, фары) | вылет `0x004C7DAD` (нет колеса) |
| `veh.dummy_side` | фреймы `_lf`/`_lb`/`ped_arm` слева (x < 0), `_rf`/`_rb` справа | зеркальные двери, рука снаружи машины |
| `veh.wheel_scale` | диаметр меша колеса = размер колеса из IDE (у ванили 0,99–1,03) | колёса висят или утоплены |
| `veh.shadow_mesh` | встроенная COL3 с теневым мешем | вылет `0x0070FB39` (нет модели тени) |
| `veh.env_uv2` | отблеск `xvehicleenv128` только на геометрии со вторым UV-набором | невидимый отблеск краски |
| `veh.light_key_tex` | цвета-ключи фар только на `vehiclelights128` | фары не загораются |
| `veh.paint_dirt` | основная краска на `vehiclegrunge256` | кузов никогда не пачкается |
| `veh.upgrade_frames` | фреймы `ug_*` заменяемой ванильной модели | вылет `0x007F0BF7` (деталь тюнинга) |
| `veh.hd_tris`, `veh.part_tris` | треугольники модели высокой детализации (кузов + части + колесо один раз) и каждой части | бюджеты уровня |
| `veh.dam_ratio` | медиана отношения треугольников `_dam`/`_ok` в пределах ванили 0,5–1,4 | урезанные части повреждений |
| `dff.flat_shading`, `dff.vert_sharing` | изгиб нормалей машин и педов выше нижней границы класса; вершины разрезаны по граням при плоских нормалях | гранёный вид |
| `ped.skin` | 32 кости, не больше 4 весов, индексы костей в пределах | вылет `0x007C4781` (скин) |
| `weap.flash` | текстурированный атомик `gunflash` у огнестрела | выстрелы без вспышки |
| `col.face_light_zero` | все грани коллизии с освещением 0 | тёмные педы, у машин горят фары |
| `ide.draw_bigbuilding` | дальность прорисовки > 300 у модели с коллизией | коллизия выключена |
| `mat.alpha_draw_last` | полупрозрачные цвета материалов без флага `draw_last` (выключено в `game`/`vanilla`: ваниль так делает у 42 % таких моделей) | спрятанная за стеклом геометрия |

`dff.flat_shading` берёт числа затенения из `satk.style` (`shade.normal_bend`, `shade.flat_share`). Если и
медианный сгиб между соседними гранями мал (меньше половины ванильного p10 для машин, 7,9°; у ванильных машин
7,9 / 11,7 / 21,4° на p10 / p50 / p90), сообщение добавляет, что модель в основном из плоских панелей: другие
нормали их не скруглят, кузову нужны дополнительные сегменты кривизны.

Каждое включённое правило таблицы срабатывает не больше чем на 2 % того, что оно проверяет в ванильной игре
(`--baseline vanilla` показывает долю). Записи 2DFX (вылет `0x00B4C2DD`) проверяет `satk fx2d check`: см.
[fx2d.md](fx2d.md).

## Ответы с учётом эталона

- `--baseline vanilla` один раз проверяет всю ванильную игру тем же пресетом (≈20 с, потом из кэша в
  `work\cache\lint\`), добавляет столбец `vanilla_rate` (доля проверенных в ванили объектов, где правило
  срабатывает) и убирает находки правил, которые сама ваниль даёт не меньше чем в `--baseline-rate` (по
  умолчанию 0,05) случаев, — например, отсутствие мипмапов. <!-- linkcheck: ignore -->
- `--like model:426` проверяет эту эталонную модель (её DFF, цепочку TXD и COL) и убирает правила, которые
  срабатывают и на ней.
- `suppressed` перечисляет убранные правила с числом находок; `--sev info` по-прежнему показывает остальное.

## Как это устроено

- Проверки — модули `dff`, `txd`, `col`, `ide`, `link` и `semantics` пакета `satk.lint`; разбор — `satk.formats`.
  Код только сообщает «сработало правило X с такими полями»; серьёзность, пороги, текст, исправление (`hint`) и
  предотвращаемый вылет берутся из `data/lint_rules.json`.
- Класс модели (для prelight, нормалей, бюджетов и смысловых правил) берётся из IDE: `objs`/`tobj` → `map` (или
  `lod`, если в имени есть `lod` или дальность больше 300; `pickup` для моделей пикапов; `upgrade` для
  `veh_mods.ide`; `interior_prop`/`interior_shell` для IDE интерьеров и `gta_int.img`), `cars`, `peds`, `weap`,
  остальное — `other`. Одиночный файл без IDE и без индекса угадывается: со скином — `peds`, со встроенной
  коллизией — `cars`, иначе `map`. Записи `player.img` — одежда (`other`).
- Метрики затенения следуют `satk.style` (`shade.normal_bend` — взвешенный по площади угол между нормалями углов
  и нормалью грани; у ванильного `premier` 10,64°); если `satk.style` установлен, используется его реализация.
- Связи: модель IDE → `<имя>.dff`, TXD из IDE → его родители `txdp` → `vehicle` для машин; COL-модель с тем же
  именем (≤ 21 символа) для объектов карты (кроме LOD); текстуры материалов ищутся по всей цепочке. Сироты (DFF,
  TXD или COL без модели) — `info`/`warn`.
- Боксы COL по формату — AABB (`CColBox = {min, max}`), вращения в файле нет. Повёрнутый или отражённый бокс,
  выгруженный как AABB, ловится как `min > max` (`col.box_inverted`) или как примитив вне границ модели
  (`col.outside_bounds`).
- Детерминизм: одинаковый вход — одинаковый ответ (сортировка по серьёзности, файлу, правилу). `--save` пишет все
  находки в `work\out\lint\<цель>-<хэш>.json`; имя зависит только от цели, пресета и правил. <!-- linkcheck: ignore -->

## Ограничения и известные проблемы

- Лимиты пулов (`limit_def`, число моделей, слотов TXD и COL) и конфликты ID с SA-MP пока не проверяются.
- Ванильные заглушки (`special01…`, `cutobj*`, `clothes*`, `null`, `airtrain_vlo`) не считаются пропавшими
  моделями; список — в параметрах `link.dff_missing`.
- Без индекса и без IDE в цели проверки связей пропускаются (линтер не знает, какие модели есть в игре);
  `veh.upgrade_frames` и распознавание огнестрела в `weap.flash` требуют индекс.
- Бюджеты `sa_plus` — предложение: они помечены так, пока не проверены рядом с ванилью в игре.

## Python-API (если другие пакеты его используют)

```python
from satk.lint.runner import lint
rep = lint("models/gta3.img", preset="sa_plus", only=["veh", "dff.flat_shading"])
print(rep.summary, rep.checked, [f.row() for f in rep.at_least("warn")])
```
