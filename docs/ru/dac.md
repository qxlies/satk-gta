# Файл DAC: кэш производных данных, раскладка байтов, формат 1.0

[English version](../en/dac.md)

Пакет: `satk.pack` (`satk pack dac`, `verify`, `inspect`; см. [pack.md](pack.md)). Таблицы на этой странице печатаются из
кода (`satk.pack.layout`), и тест их сверяет.

## Что это

Модифицированному рендереру нужны данные, которых в обычных файлах нет или которые там плохи. Большая часть геометрии
карты с запечённым освещением и без нормалей вершин; ночные цвета лежат в чанке-расширении, которое GPU не прочитает как
вершинный поток; тангенты, список источников света модели и цепочки mip текстур пересчитывались бы снова и снова.
**Файл DAC** хранит такие производные данные одного исходного ассета, вычисленные один раз.

- **Адресация по содержимому.** Файл называется своим **ключом кэша**: `SHA-256("DACKEY1" 0x0A, SHA-256 источника,
  u32 derive_id, канонический JSON параметров)`. Другой источник, другая версия рецепта или другие параметры дают другой
  ключ, поэтому устаревший файл никогда не находится. Канонический JSON — с отсортированными ключами, без пробелов,
  только ASCII.
- **Только локально.** DAC получается из собственных файлов пользователя. Он создаётся на его машине в
  `<workspace>/work/cache/dac/<hh>/<key>.dac`, не распространяется и не коммитится; пак с данными DAC ставит флаг
  `local_only`.
- **Данные на вершину индексируются индексом вершины геометрии в исходном файле.** `count` потока равен числу вершин
  геометрии, поэтому шейдер может подключить поток рядом с собственным вершинным буфером геометрии.

Все целые числа — little-endian.

## Раскладка файла

```
0                         заголовок (128 байт)
128                       таблица секций (64 байта на секцию)
...                       данные секций, каждая с выравниванием 16 байт, добито нулями
```

Секция meta (параметры вывода в JSON) всегда последняя.

### Заголовок

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | u8[8] | `magic` | ASCII SAEDACFL |
| 8 | u16 | `major` | старшая версия формата (1) |
| 10 | u16 | `minor` | младшая версия формата (0) |
| 12 | u32 | `header_size` | 128 |
| 16 | u32 | `flags` | 0 |
| 20 | u32 | `section_count` | записей в таблице секций |
| 24 | u32 | `derive_id` | рецепт вывода (1 = потоки DFF, версия 1) |
| 28 | u32 | `source_kind` | 1 dff, 2 txd, 0 прочее |
| 32 | u64 | `section_table_off` | абсолютное смещение таблицы секций (128) |
| 40 | u64 | `file_size` | размер всего файла |
| 48 | u8[32] | `source_sha256` | SHA-256 байт исходного ассета, из которого получен кэш |
| 80 | u8[32] | `cache_key` | SHA-256 от DACKEY1, source_sha256, derive_id и канонического JSON параметров |
| 112 | u32 | `crc32` | CRC-32 (zlib) байт заголовка 0..111 |
| 116 | u8[12] | `reserved` | ноль |

Читатель проверяет сигнатуру, CRC заголовка, старшую версию, что `file_size` равен настоящему размеру, что таблица секций
помещается в файл и, после чтения секции meta, что `cache_key` равен ключу, пересчитанному из `source_sha256`,
`derive_id` и параметров.

### Таблица секций

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | u16 | `kind` | 1 geom_stream, 2 light_list, 3 mip_chain, 4 meta |
| 2 | u16 | `stream` | тип потока геометрии: 1 normal, 2 night_color, 3 tangent (0 для других видов) |
| 4 | u32 | `index` | индекс геометрии в источнике (порядок в потоке по всем clump) или индекс текстуры |
| 8 | u32 | `count` | элементов: вершин, источников света или уровней mip (байт для meta) |
| 12 | u16 | `format` | формат элемента, см. таблицу форматов |
| 14 | u16 | `stride` | байт на элемент (0 для bytes и json) |
| 16 | u64 | `offset` | абсолютное смещение данных (кратно 16) |
| 24 | u64 | `size` | размер данных в байтах (count * stride при фиксированном шаге) |
| 32 | u32 | `crc32` | CRC-32 (zlib) данных |
| 36 | u32 | `flags` | бит 0: вычислено satk (не скопировано из исходного файла) |
| 40 | u32 | `aux0` | mip_chain: формат D3D9 (FOURCC или номер D3DFMT); иначе 0 |
| 44 | u32 | `aux1` | mip_chain: ширина первого сохранённого уровня; иначе 0 |
| 48 | u32 | `aux2` | mip_chain: высота первого сохранённого уровня; иначе 0 |
| 52 | u32 | `aux3` | mip_chain: индекс первого сохранённого уровня (0 = вся цепочка); иначе 0 |
| 56 | u64 | `reserved` | ноль |

Секции отсортированы по `(kind, index, stream)`; эта тройка уникальна. Каждые данные защищены собственным CRC-32.

### Виды секций

| Вид | Имя | Данные |
|---:|---|---|
| 1 | `geom_stream` | один поток на вершину одной геометрии (`index` — индекс геометрии, `stream` — тип потока) |
| 2 | `light_list` | источники света одной геометрии: `count` записей `LIGHT_V1` |
| 3 | `mip_chain` | производные уровни mip одной текстуры: `count` уровней, плотно, от первого сохранённого уровня вниз; `aux0` — формат D3D9 (FOURCC вроде `DXT1` как little-endian u32 или номер `D3DFMT`), `aux1` x `aux2` — размер первого сохранённого уровня, `aux3` — его индекс (0 = вся цепочка) |
| 4 | `meta` | JSON (UTF-8) с параметрами вывода |

### Типы потоков геометрии

| Поток | Имя | Формат | Значение |
|---:|---|---|---|
| 1 | `normal` | `oct16x2` (или `f32x3`) | единичная нормаль вершины; бит 0 флагов говорит, что её вычислил satk |
| 2 | `night_color` | `rgba8` | ночные цвета вершин как в файле, готовые к смешиванию день/ночь на GPU |
| 3 | `tangent` | `snorm8x4` | тангент x, y, z и знак битангента, из UV-набора 0 |

### Форматы элементов

| Id | Имя | Шаг | Кодирование |
|---:|---|---:|---|
| 1 | `f32x3` | 12 | три 32-битных float |
| 2 | `f32x4` | 16 | четыре 32-битных float |
| 3 | `oct16x2` | 4 | октаэдрическая развёртка единичного вектора, два snorm16 (`D3DDECLTYPE_SHORT2N`), ниже |
| 4 | `rgba8` | 4 | байты r, g, b, a в порядке потока вершинных цветов RenderWare |
| 5 | `snorm8x4` | 4 | четыре знаковых байта: `round(v * 127)` для x, y, z; w равно +127 или -127 (знак) |
| 6 | `light_v1` | 32 | запись источника света, ниже |
| 7 | `bytes` | 0 | произвольные байты (уровни mip) |
| 8 | `json` | 0 | JSON (UTF-8) |

**Октаэдрические нормали.** Кодирование: `n = |x| + |y| + |z|`; `(px, py) = (x / n, y / n)`; если `z < 0`:
`(px, py) = ((1 - |py|) * sgn(px), (1 - |px|) * sgn(py))`, где `sgn(0) = +1`; хранится `round(p * 32767)` как два
знаковых 16-битных целых (нулевой вектор хранится как `(0, 0)`). Декодирование: `p = хранимое / 32767`; `z = 1 - |px| - |py|`;
если `z < 0`, к `(px, py)` применяется та же развёртка; нормировать `(px, py, z)`. Ошибка круга преобразований меньше 0,01
градуса.

**`LIGHT_V1`** (32 байта):

| Смещение | Тип | Поле | Значение |
|---:|---|---|---|
| 0 | 3 x f32 | `x, y, z` | позиция в системе координат геометрии, как в записи 2dEffect |
| 12 | 4 x u8 | `r, g, b, a` | цвет света |
| 16 | f32 | `corona_far_clip` | расстояние, дальше которого корона не рисуется |
| 20 | f32 | `point_range` | радиус точечного света |
| 24 | f32 | `corona_size` | размер короны |
| 28 | u32 | `flags` | флаги света 2dEffect: первый байт флагов, второй байт флагов, сдвинутый влево на 8 |

## Рецепт 1 (`derive_id` 1): потоки DFF

`satk pack dac` заполняет такие секции для каждой геометрии DFF (геометрии нумеруются в порядке потока по всем clump;
платформенные геометрии пропускаются):

- `normal`: для геометрий без нормалей (`--normals missing`, по умолчанию) или для всех (`--normals all`; имеющиеся
  нормали копируются, бит 0 флагов не ставится). Вычисленные нормали гладкие, взвешены по углам при вершине, с жёстким
  ребром там, где грани сходятся под углом больше `--angle` градусов (по умолчанию 45) или через шов материала; вершины
  в одной точке делят нормали граней, записи вершин никогда не склеиваются.
- `night_color`: расширение ночных цветов геометрии, если оно есть и содержит цвета.
- `tangent`: из UV-набора 0, ортогонализован к нормали; у геометрий без UV или треугольников его нет.
- `light_list`: записи 2dEffect типа 0 (источники света) геометрии.

Параметры, сохраняемые в секции meta (и входящие в ключ кэша): `normals`, `tangents`, `night`, `lights` и `angle`.

## Проверка

`satk pack verify file.dac` сообщает первую структурную проблему как ошибку: `BAD_MAGIC`, `DAC_CRC` (заголовок или
данные), `BAD_VERSION`, `SIZE_MISMATCH`, `DAC_FORMAT` (таблица, вид или формат не подходят), `DAC_RANGE` (данные вне файла
или невыровнены), `CACHE_KEY` (ключ не соответствует содержимому). Предупреждения: `RESERVED` (зарезервированное поле не
нуль), `STREAM_UNKNOWN`; ошибка `SECTION_DUP` (одна тройка `(kind, index, stream)` дважды).

## Правила совместимости

Те же, что в [saepak.md](saepak.md): читатель принимает свою старшую версию и игнорирует более поздние дополнения младшей
(`header_size` и таблица секций говорят, где что лежит), зарезервированные поля — нули, каждое смещение и число
проверяются по размеру файла до использования. Изменение рецепта получает новый `derive_id`, что меняет все ключи кэша.
