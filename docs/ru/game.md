# `satk game`: чистая копия игры

[English version](../en/game.md)

Пакет: `satk.game`.

## Что это

`satk game` отвечает за чистую копию игры (`paths.game`, по умолчанию `<workspace>\gta-sa-clean`): проверяет её,
защищает IMG-архивы от записи, воспроизводит копию из оригинальной установки и записывает нужный вариант
`gta_sa.exe`. Оригинальная установка (`paths.installed`) только читается: в неё не пишет ни одна команда.

В проверенной чистой копии 416 файлов, 5 029 186 364 байта и стоковый `gta_sa.exe` 1.0 US HOODLUM. Создаётся она
командой `satk init --clean-copy` (только для стоковой 1.0 US) или `satk game clone`.

## Быстрый пример

```powershell
satk game info --table
satk game verify
```

Что вернёт `verify` (сокращённо):

```json
{"ok":true,"root":"<workspace>/gta-sa-clean","files":416,"bytes":5029186364,"mismatch":0,"missing":0,"extra":0,"exe":"hoodlum-stock","manifest":"ok","protected":"8/8","mode":"fast","hashed":376,"fast":40,"seconds":0.1}
```

## Команды

| Команда | MCP | Что делает |
|---|---|---|
| `satk game verify [--root R] [--deep] [--against stock\|install] [--scope stock\|all]` | `satk_op` | Сверяет каталог с манифестом. По умолчанию быстро: IMG и `audio\` по размеру и mtime, остальное по SHA-256 (около 0,2 с при тёплом кэше). `--deep` хэширует все 5 ГБ (около 3–10 с на NVMe) |
| `satk game info [--root R]` | `satk_op` | Вариант и раскладка `gta_sa.exe`, `vorbisFile.dll`, число ASI, нестоковые файлы, защита IMG |
| `satk game protect` / `unprotect [--root R]` | `satk_op` | Ставит или снимает атрибут «только чтение» у 8 IMG-архивов |
| `satk game clone [--src S] [--dst D] [--exe stock\|mta] [--dry-run] [--protect]` | `satk_op` | Воспроизводит копию в **новый** каталог |
| `satk game exe [--variant stock\|mta] [--out F] [--src E] [--force]` | `satk_op` | Записывает стоковый или MTA-канонический exe вне каталогов игры |

Своего MCP-инструмента у `game` нет: агент находит команды через `satk_ops("game")` и запускает через `satk_op`.
Вывод — JSON-конверт; `--table` печатает таблицу. Другие параметры: `--jobs` (потоки хэширования или копирования),
`--limit` (сколько строк отличий в ошибке `verify`), `--manifest` (другой манифест — для тестов и других версий игры).

### `verify`

- `--against stock` (по умолчанию): эталон — `data/manifests/stock-1.0us-hoodlum.json` (416 файлов). Дополнительно
  сверяется `MANIFEST.sha256` в корне копии (поле `manifest`: `ok`, `differs` или `missing`). Сам `MANIFEST.sha256`
  лишним файлом не считается.
- `--against install`: эталон — аудит одной оригинальной установки с модами `data/manifests/install-<дата>.json`
  (549 файлов; это данные разработчиков, в публичный репозиторий они не входят; корень по умолчанию тогда —
  `paths.installed`). `--scope stock` проверяет только 416 стоковых путей; для
  `gta_sa.exe` и `vorbisFile.dll` сверяются локальные хэши аудита `1d7c531f…` и `6ccf4258…`. `--scope all`
  проверяет всё, но логи SA-MP и sanext меняются при игре.
- Лишние файлы в копии при `--scope stock` — только предупреждение `EXTRA_FILES`, при `--scope all` — ошибка.
- Если нашлись отличия, команда завершается с ошибкой `REVISION` (exit 1). В `error.data` лежат счётчики и таблица
  `path, problem, expected, actual`; `problem` — одно из `missing`, `size`, `sha256`, `extra`.
- Быстрый режим не заметит правку IMG «на месте», если размер и mtime совпали. Для полной уверенности используйте
  `--deep`. Если у IMG изменился только mtime, файл просто хэшируется, ошибки не будет.

### `info`

Без `--root` описывает чистую копию, а если её нет — папку игры (`paths.game_root`).

| Поле | Значение |
|---|---|
| `exe` | `hoodlum-stock` (сток), `hoodlum-nointro` (локальный exe с патчем пропуска заставок), `mta-canonical` (сток с исправленной контрольной суммой PE), `mta-programdata*` (рантайм-копии MTA), `compact-1.0us`, `unknown`, `missing` |
| `variant`, `layout`, `re_supported` | понятное имя сборки, её раскладка адресов (`1.0us`) и работает ли с ней `satk re`; неподдерживаемый exe добавляет предупреждение `UNSUPPORTED_EXE` (ассеты работают с любой версией) |
| `variant_match` | как опознан exe: `sha256` (проверенный хэш из `data/exe_versions.json`), иначе по сигнатурам байтов или размеру файла (эвристика) |
| `exe_sha256`, `exe_desc`, `exe_pe` | хэш, описание и поля PE-заголовка exe |
| `vorbisfile` | `stock` или `asi-loader` (ASI Loader от Silent занял имя `vorbisFile.dll`) |
| `asi` | число `*.asi` во всём дереве |
| `nonstock` | файлы вне стокового набора; первые 20 — в `nonstock_files`, разбивка — в `nonstock_roles` (`exclude` — добавки внутри стоковых папок, `nonstock` — всё остальное) |
| `stock_present`, `stock_missing`, `files` | сколько стоковых файлов найдено и не хватает, всего файлов в папке |
| `manifest` | есть ли в папке `MANIFEST.sha256` |
| `protected` | сколько из 8 IMG имеют атрибут «только чтение» |

Для чистой копии: `exe=hoodlum-stock`, `asi=0`, `nonstock=0`, `protected=8/8`. Для проверенной оригинальной
установки: `hoodlum-nointro`, `asi-loader`, 17 ASI, 133 нестоковых файла.

### `protect` / `unprotect`

Защищаются `models\{gta3,gta_int,player,cutscene}.img`, `anim\{anim,cuts}.img`, `data\paths\carrec.img`,
`data\script\script.img`. Игра и Ariane открывают IMG на чтение (`"rb"`), поэтому защита им не мешает. Попытка
записи (например, «сохранить» в редакторе) получит отказ ОС вместо тихой порчи архива. Содержимое и mtime не
меняются, `verify` остаётся `ok`.

Рабочее состояние копии — **защита включена**. Снимать её нужно только на время осознанной правки. Оригинальную
установку команда защищать отказывается (`PROTECTED_PATH`): туда satk не пишет даже атрибуты. `--root` — это сама
чистая копия или копия под `work\`; подкаталог чистой копии, место вне `work\` и IMG с жёсткими ссылками (атрибут
общий для всех имён файла) — тоже `PROTECTED_PATH`.

### `clone`

1. Источник (по умолчанию оригинальная установка) открывается только на чтение. Источником может быть и
   проверенная чистая копия (`--src <workspace>\gta-sa-clean`): её `vorbisFile.dll` уже оригинальный, а exe
   (стоковый или MTA) приводится к нужному варианту.
2. `dst` должен быть новым или пустым каталогом, иначе `EXISTS`. Разрешены только каталог под `work\` или сам
   корень чистой копии (`paths.game`, если его нет или он пуст). Всё остальное — `PROTECTED_PATH` (см. «Куда game.*
   разрешено писать»).
3. Каждый из 416 файлов копируется в `<dst>.partial` с хэшированием и сверкой с манифестом; mtime сохраняется.
4. `gta_sa.exe` восстанавливается в памяти: откат 12 байт патча «без заставок» по смещению в файле `0x347EA8`.
   Вариант `--exe mta` дополнительно исправляет поле CheckSum PE на `0xDBD689`.
5. `vorbisFile.dll` берётся из `vorbisHooked.dll` (у чистой копии — из самого `vorbisFile.dll`).
6. Затем пишется `MANIFEST.sha256`, и `<dst>.partial` атомарно переименовывается в `<dst>`. Первая же ошибка хэша
   (или Ctrl+C) останавливает все копирования: очередь отменяется, идущие копии прерываются на текущем буфере
   (1 МБ), частичная копия удаляется.

Пропускаются `*.two`, `data\colorcycle.dat`, `models\{ps3btns,x360btns,sixaxis}.txd`, `text\languages.ini` и всё
вне `anim, audio, data, models, movies, text, ReadMe` и корневых `eax.dll, ogg.dll, vorbis.dll, stream.ini` —
итого 133 файла проверенной установки. Нужно около 5,03 ГБ свободного места.

`--dry-run` ничего не пишет и печатает план:

```powershell
satk game clone --dst <workspace>\work\tmp\clone --dry-run
```

```json
{"ok":true,"files":416,"bytes":5029186364,"skip_nonstock":133,"restore":["gta_sa.exe","vorbisFile.dll"],"exe":"hoodlum-stock","free_bytes":27503448064,"dry_run":true}
```

### `exe`

```powershell
satk game exe --variant mta --out <workspace>\work\re\bin\gta_sa_mta.exe
```

Источник по умолчанию — `gta-sa-clean\gta_sa.exe`, если его нет — exe оригинальной установки. Подходит любой
вариант, из которого выводится сток: `hoodlum-stock`, `hoodlum-nointro`, `mta-canonical`. Результат проверяется по
SHA-256 до записи:

- stock: `a559aa772fd136379155efa71f00c47aad34bbfeae6196b0fe1047d0645cbd26`;
- mta: `f63fa623d14e170d0ae9e7032186669cf3a177793be21c4824043f0279bd506a`.

По умолчанию файл пишется в `work\re\bin\gta_sa_<variant>.exe`. `--out` — только под `work\` и не внутри
git-репозитория (например, worktree под `work\wt\`): исполняемый файл игры не должен попасть в `docs` или в коммит.
Если файл с другим содержимым уже есть, нужен `--force`.

## Куда game.* разрешено писать

`clone --dst`, `exe --out` и `protect/unprotect --root` проверяет `satk.game.guard`, и пишется ровно тот путь,
который проверен:

1. Написание пути приводится к одному виду: `\\?\D:\…`, `\\.\D:\…`, `//?/D:/…` → `D:\…`. Другие пространства имён
   (`\\?\Volume{…}`, `GLOBALROOT`, устройства), компоненты с точкой или пробелом на конце и `..` внутри
   `\\?\`-пути — `BAD_PARAMS`. Сетевые пути (`\\localhost\D$\…`, `\\?\UNC\…`, сетевой диск) — `PROTECTED_PATH`:
   шара может оказаться той же оригинальной установкой.
2. Junction, symlink и подставленные диски раскрываются (`realpath`).
3. Текстовая проверка защищённых корней (`paths.ensure_writable`). Блокировка чистой копии снимается только для
   самого её корня, не для подкаталогов.
4. Проверка по идентичности файла (`os.path.samestat`): ни один существующий предок цели не может быть тем же
   каталогом, что оригинальная установка, `src` или другой защищённый корень, как бы он ни был записан.
5. Место: под `work\` (или корень чистой копии там, где это разрешено) и вне git-репозиториев.

## Данные в репозитории

В репозитории лежат только пути и хэши, байтов игры нет:

- `data/manifests/install-<дата>.json` (только в клонах разработчиков, не в публичном репозитории) — аудит одной
  оригинальной установки, 549 файлов `{size, sha256, mtime}`;
- `data/manifests/stock-1.0us-hoodlum.json` — 416 файлов чистой копии, правила отбора, целевые хэши exe и
  `vorbisFile.dll`. Генерируется из аудита командой `python -m satk.game.manifests build`; тест проверяет, что
  закоммиченный файл воспроизводится байт в байт. Текст `MANIFEST.sha256` копии тоже воспроизводится из него байт в
  байт;
- `data/exe_versions.json` — известные сборки `gta_sa.exe` (хэш, сигнатуры, размер, раскладка) для `info`.

В установленном пакете эти файлы лежат в `satk/_data`.

## Для разработчиков

- Код только на stdlib. Игровые файлы открываются через `paths.open_ro` (`"rb"`). Цели записи проверяет
  `satk.game.guard.write_target`, каждый файл — `ensure_writable`; `game_writer()` включается только для корня
  чистой копии (`Target.unlock()`).
- Пути внутри игры сравниваются как в Windows: без учёта регистра, `\` и `/` равнозначны. Строятся только через
  `pathlib` по компонентам. Строковые литералы с экранированием `\x` в `satk/game` запрещены: прототип превращал
  `"models\x360btns.txd"` в `models60btns.txd`. Это проверяет тест.
- Тесты: `tests/game` (синтетические установки генерируются в `tmp`, назначения — в `work` изолированного рабочего
  пространства, фикстура `work`); тесты с маркером `game` читают настоящие чистую копию и оригинальную установку
  только на чтение и пишут в свой `SATK_PATHS_WORK` (фикстура `real_work`).
- `satk status` (секция `game`) и `satk doctor` (проверка `game_copy`) берут данные из этого пакета.
