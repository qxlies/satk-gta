# Вид: превью в стиле SA для моделей игры, своих файлов и живых сессий

[English version](../en/look.md)

Пакет: `satk.look` (MIT) и `blender/satk_blender/look` (GPL-3.0-or-later).

## Что это

`satk blender preview` показывает модель так, как её рисует San Andreas, чтобы ИИ-ассистент или человек мог
оценить новый ассет рядом с ванильными на одной маленькой картинке. Предметом может быть модель игры
(`model:426`), свой файл `.dff` (`.txd` рядом с ним находится сам), целая папка мода или сцена живой сессии
студии (`session:NAME`). Ответ — один лист JPEG не больше 1024 пикселей и 300 КБ и числа затенения каждой
модели (те же, что у `asset check`). Всё пишется в `<workspace>\work\out\preview\` и `<workspace>\work\blender\`;
ваши файлы и игра только читаются.

Игровой вид повторяет движок: стекло прозрачное (альфа материала), каждая фара на `vehiclelights128` белая
(горит с `--lights on`), кузова получают уровень грязи 0..16 текстуры `vehiclegrunge256` по формуле,
восстановленной из exe (по умолчанию 2, слегка поездившая машина), окружение и блики MatFX берутся из DFF,
модели карты используют своё дневное и ночное предосвещение плюс фоновый свет `timecyc.dat` для выбранного
времени, а кадр получает цветовой фильтр и гамму экрана игры. Педы стоят прямо, вспышки выстрела скрыты; стоящий
вертолёт, самолёт или катер показывает неподвижный винт (вращающиеся диски появляются только на ходу).

На той же сцене работают два инструмента осмотра: **крупные планы по зонам** (`--regions`) рисуют каждую зону
осмотра своего вида ассета отдельным листом (у машины: перед, зад, левый и правый бок, колёса с арками, днище,
салон, крыша; у здания: каждый фасад, крыша, вход, сравнение с LOD; у предмета: стороны, верх, основание, детали;
у каждого вида свой список), а **проверка просветов** (`satk look leak` или проход `--passes leak`) находит места,
где сквозь модель виден фон: просветы между деталями, открытые оболочки, грани, которые игра отсекает.

## Быстрый пример

```powershell
satk blender preview model:426 --views 3q,side --states ok,dam
satk blender preview model:426 --lineup model:405,model:560 --passes game,wire
satk blender preview model:400 --regions front,wheels --passes game,leak
satk look leak model:400 --regions wheels
```

Что возвращает первая команда (сокращённо):


## Команды

| Команда | MCP | Что делает |
|---|---|---|
| `satk blender preview <subject>` | — (`satk_op`) | один лист: ракурсы x состояния x проходы x время и числа затенения |
| `--like model:426` | | модель игры, которую заменяет файл: её класс, окраска и опора линейки (сессия проекта ассета берёт её из `asset.json`) |
| `--lineup class` или `--lineup model:405,model:560` | | предмет рядом с образцом и его одноклассниками (или заданными моделями) в одном масштабе, на одной земле |
| `--views 3q,rear3q,front,rear,side,top` | | камеры (по умолчанию `3q,rear3q,side,top`; у линейки `side,3q`) |
| `--passes game,clay,wire,raw,tex` | | игровой вид, серая глина, глина с рёбрами треугольников, материалы как импортированы, свои текстуры в родном масштабе (PNG) |
| `--states ok,dam,vlo,col` | | целая, повреждённые части, дальний LOD, коллизия |
| `--time 12:00,23:00` `--lights on` `--dirt 0..16` | | время суток (по строке на каждое), фары включены, уровень грязи |
| `--context 60` (с предметом `inst:`) | | расстановка в окружении карты |
| `--timeout 60` | | сколько секунд может работать Blender: 60 в живой сессии (она затем останавливает превью и остаётся рабочей), 300 для холодного задания |
| `--ref photo.jpg [--ref-view side\|front\|rear] [--ref-flip] [--ref-box x0,y0,x1,y1]` | | НАСТОЯЩИЙ вид сбоку, спереди или сзади (снятый издалека, оба колеса круглые) рисуется за предметом в этом ракурсе игрового прохода на 30 % и масштабируется так, чтобы объект на фото занимал предмет (он ищется по цвету краёв фото или задаётся `--ref-box`); вид сбоку показывает перед слева, `--ref-flip` отражает фото, где машина смотрит вправо. Проверка контура без чисел; никогда не для фото в три четверти |
| `satk blender call look.render --session N --params '{"views":["3q"]}'` | — | игровой вид внутри живой сессии; как и превью, ставит колесо на каждый держатель колеса и окрашивает ключи краски (`colors`, по умолчанию синий цвет новой модели) только на время рендера |
| `satk blender call look.silhouette --session N --params '{"ref":"side.jpg","view":"side"}'` | — | силуэт модели против настоящего вида сбоку, спереди или сзади: перекрытие (IoU), линия верха на 20 станциях вдоль длины в метрах (`worst` — самые большие расхождения) и PNG наложения; сведения для критика, а не проверка |
| `satk model image <file.dff>` | `model_image` | программное превью без GPU, теперь с теми же правилами грязи, фар и света |
| `--regions all` или `--regions front,wheels` `[--kind automobile]` | | крупные планы зон осмотра вида предмета: по листу на зону `preview-NNN-<зона>.jpg` (один `NNN` на запуск) и лист-оглавление `preview-NNN-index.jpg`; ответ перечисляет зоны и что в них проверить. Вид берётся из `--kind`, `asset.json`, строки индекса модели (или `--like`), иначе по именам кадров |
| `--passes leak` | | ячейка проверки просветов для каждого ракурса (см. ниже) и найденные просветы в ответе |
| `satk look leak <subject> [--regions ...] [--views ...] [--package <dir>]` | — (`satk_op`) | проверка просветов с камер осмотра вида: один лист, просветы (`id kind region view area_cm2 point near seen_in`), `clean`; `--package` пишет `<dir>/checks/<stem>.leak.json` (папка экспортированного DFF; по файлу на DFF), его читает `asset check --strict` (он принимает только полный прогон: все зоны просветов вида, настройки по умолчанию) |
| `satk blender call look.leak --session N --params '{"kind":"automobile"}'` | — | та же проверка для сцены живой сессии |

## Как это работает

satk превращает предмет в планы моделей (копии в кэше `work`), считает числа затенения по байтам DFF и запускает
одно задание Blender без окна (или метод студии `look.preview` внутри сессии, где модели линейки импортируются и
затем удаляются). Игровой вид — одна общая группа узлов, поэтому EEVEE компилирует мало шейдеров, а каждый
материал берёт самый лёгкий её вариант (без прозрачной ветви, без дневной/ночной ветви, без окружения и блика,
если они не нужны), потому что EEVEE синхронизирует каждый материал при каждом рендере. Холодное превью
4 ракурсов x 2 состояний занимает около 5 с, превью в сессии — около 1,1 с (первое в свежей сессии — примерно на
0,5 с дольше, пока компилируются шейдеры). Ячейки сохраняются в PNG без потерь; лист собирается и кодируется на
стороне satk. Тот же вызов использует ту же папку вывода; каждый запуск оставляет свой лист `preview-NNN.jpg` (его
называет ответ; `preview.jpg` — последний), а запуск, нарисовавший те же пиксели, берёт самый новый номер.

Одноклассники для `--lineup class` берутся из набора образцов стиля (того же, что у `style profile` и
`asset check`, например `car.sedan` или `prop@1-2m`): сначала модели, в имени которых есть слово из имени
образца (урна `bin1` получает `CJ_WASTEBIN` и `CJ_BIN1`, а не любой предмет размером 1-2 м), затем ближайшие по
форме и числу треугольников; ответ называет набор в `NOTE`. Сессия проекта ассета без `--like` берёт образец из
`asset.json`, а если его нет — вид ассета и целевой размер. Сцена самой сессии показывается так, как игра
показывает импортированную модель: колесо на каждом держателе колеса и, у машины, окраска образца на ключах
окраски (только на время рендера); слот LOD здания — это состояние `vlo`. Класс модели сессии определяется по
её меткам, а не только по сеткам: `satk_sec` на объектах кадров kit и на частях заготовки, группа коллекции kit,
заготовка транспорта, пустышки сцены (держатели колёс, `chassis_dummy`). Поэтому машина из сессии всегда получает
игровой вид машины: ключи краски заменены (цвета образца или синий цвет новой модели, никогда не зелёный ключ) и
уровень грязи 2 на `vehiclegrunge256`.

### Зоны осмотра

Зоны каждого вида — это данные: `data/kit/regions/<вид>.json` (все виды kit, а ещё `lod` и `terrain` для LOD
карты и больших плоских кусков земли: без камер с уровня улицы). Зона называет, что проверять и
как это снять: камеры по азимуту и высоте (`az` 0 — спереди, 90 — справа, -90 — слева, либо `out` — со стороны,
где стоит её кадр), рамка в долях модели (x слева направо, y сзади вперёд, z снизу вверх) или кадры
(`wheel_*_dummy`: по крупному плану на колесо) и настройки рендера (скрыть двери и стёкла в разрезе салона, без
земли под видом снизу, состояние `vlo` рядом с `ok` для LOD здания, камеры внутри комнаты интерьера). Зона-рамка
кадрируется по точкам, разнесённым по треугольникам, поэтому стена, проходящая сквозь неё, учитывается; зону, в
которой у модели нет поверхности, пропускают (пометка `SKIPPED` и файл `preview-NNN-<зона>.skipped.txt`). Зона
`lod` модели карты показывает её LOD: LOD из IPL у игровой модели или LOD-DFF рядом с файлом (его называет файл
инвентаря kit, иначе `lod<имя>.dff`); без него ответ говорит NOT_FOUND. Камеры внутри с `rooms` стоят в каждой
комнате: грани пола под потолком, сгруппированные по этажам и по соседним клеткам 1 м, по точке на комнату на
высоте глаз (до шести комнат, сначала самые большие).

### Проверка просветов

Каждый пиксель камеры осмотра — луч сквозь модель (BVH её видимых сеток, без рендера). Луч следует движку: стекло
и текстуры с альфой его пропускают; у транспорта задняя грань его останавливает (транспорт рисуется с обеих
сторон), у всего остального она пропускается (объекты мира, педы и оружие рисуются с отсечением задних граней,
если флаг IDE `0x200000` не отключает отсечение). Ячейка — чёрная модель на светлом фоне, просветы закрашены и
обведены:

- `gap` (красный): фон виден между деталями, внутри контура модели и сквозь её оболочку (луч вверх упирается в
  оболочку изнутри) — дыра сквозь кузов, щель между панелями. Рейлинги, спойлеры и открытые рамы лежат вне оболочки
  и не помечаются. Щели тоже просветы: полоска фона шириной до 3,5 см и площадью от 10 см2 между двумя деталями
  примерно на одной глубине, найденная замыканием силуэта модели (не рядом с колесом), — у видов карты и холодного
  оружия, а у самолётов на видах строго сверху и снизу (корни крыльев); у дорожного транспорта щели не ищутся
  (рейлинги, дуги и решётки там отстоят по замыслу);
- `inside` (оранжевый): транспорт показывает изнанку своей оболочки через проём; это дефект на крупных планах колёс,
  если внутренняя поверхность не ближе 1 м за проёмом и проём от 60 см2 (открытая арка показывает дальний борт
  кузова); в остальных ракурсах это сведения (`info`, бледный цвет);
- `see_through` (пурпурный): на луче только отсечённые задние грани, игра показывает фон: дыра внутрь оболочки —
  дефект (отсечённые грани лежат за краем проёма или кусок не плоский); изнанка односторонней плоскости (забор,
  карточка фасада), видимая сзади, — это сведения. Задние грани, встреченные по касательной, и передняя грань,
  лежащая на задней (двусторонняя карточка), не считаются;
- `escape` (красный): камера внутри комнаты видит пустоту сквозь трещину (щель до 12 см; дверной или оконный проём —
  это сведения).

Калибровка: ни одного просвета на 55 ванильных моделях (34 машины, фургона, грузовика и автобуса, мотоциклы,
велосипед, квадроцикл, вертолёты, катера, самолёт, прицеп, поезд, предметы, здание, интерьер, оружие, пед, пикап,
деталь тюнинга); сквозные передние арки внедорожника, собранного агентом, находятся на крупных планах колёс. У
каждого просвета есть ракурс, рамка в пикселях, площадь, примерная 3D-точка (по глубине края вокруг него) и
ближайшая деталь; один и тот же просвет из нескольких ракурсов объединяется (`seen_in`). В `<stem>.leak.json`
лежат `clean`, `blocking`, `counts`, `gaps`, `info`, параметры, ракурсы, `coverage` прогона (все зоны просветов вида
с настройками по умолчанию: `full`) и SHA-256 проверенного DFF; satk ещё хранит свою запись каждого прогона
(`<work>/out/leak/records/<sha256>.json`), и `asset check --strict` не принимает файл, который с ней расходится.
После правил щелей и дыр калибровка такая: чисты 201 из 212 ванильных машин, 47 из 50 видов оружия и все взятые
педы; ванильные объекты карты по-прежнему показывают настоящие просветы (открытые задники, односторонние оболочки)
с камер фасадов.

## Ограничения и известные проблемы

- Множитель света освещаемых моделей и ночная доля ещё не откалиброваны по снимкам из игры; числа лежат в
  `satk.look.gamelook` и помечены как некалиброванные.
- Педы со скином показываются в позе привязки (без анимации).
- Сессия рендерится как есть, кроме колёс и окраски выше; состояния повреждений и LOD берутся по суффиксам имён
  `_dam`/`_vlo` и по слоту LOD набора kit.
- Проверка просветов видит только то, что видят её камеры: трещину, скрытую от всех камер осмотра, она не найдёт.
  Пороги (1 м, 60 см2, 12 см) откалиброваны по ванильным моделям; задуманные проёмы внутри оболочки закрытого
  кузова (окно без стекла) отмечаются как просветы.

## Python-API (если другие пакеты его используют)

```python
from satk.look import gamelook as G
G.dirt_rgb((120, 100, 80), 2)       # (238, 236, 233)
G.env_at("21:30")                   # свет timecyc: amb, amb_obj, dir, цветовой фильтр, баланс дня и ночи
```
