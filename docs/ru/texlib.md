# texlib: процедурные текстуры SA и использование оригинальных

[English version](../en/texlib.md)

Пакет: `satk.texlib`. Код узлов Blender: `blender/satk_blender/texlib` (GPL).

## Что это

texlib создаёт небольшие бесшовные материалы с зерном, смягчёнными деталями и цветовыми диапазонами San Andreas.
Также он ищет в индексе оригинальной игры текстуры, на которые объект карты может ссылаться напрямую, без
копирования игровых пикселей в мод. Изображения и листы образцов сохраняются в `<workspace>/work/out/texlib/`.

## Быстрый пример

```powershell
satk texlib list --no-previews
```

Таблица содержит 20 заготовок, их роли, форматы DXT и описания. Уберите `--no-previews`, чтобы запечь лист
из 20 образцов после сжатия DXT с подписями; прозрачные материалы показаны на шахматном фоне.

## Команды

Все операции доступны через общий интерфейс `satk_op`; отдельных инструментов MCP они не добавляют.

| Команда | Что делает |
|---|---|
| `satk texlib make brick --size 256 --seed 7` | Запекает заготовку и возвращает PNG, предпросмотр DXT, описание упаковки, проверки стиля и время |
| `satk texlib make plaster --size 128 --tint '#887c68'` | Задаёт оттенок, сохраняя приглушённую насыщенность и яркость данной роли |
| `satk texlib list` | Запекает недостающие образцы размером 128 пикселей и возвращает лист с подписями |
| `satk texlib vanilla brick --role wall` | Находит оригинальные кирпичные текстуры с именами TXD |
| `satk texlib vanilla asphalt --role road --colour grey` | Сортирует найденные текстуры по примерному цвету из индекса |

`make` принимает только 128 или 256 пикселей. Начальное число генератора — целое от 0 до 4294967295.
Оттенок и цвет задаются через `#RRGGBB` или имена `grey`, `brown`, `red`, `blue`, `green`, `beige`, `rust`.
`--out` задаёт **папку внутри work**, а не имя PNG. Имена папок по умолчанию включают хеш содержимого.
Одинаковые параметры повторно используют проверенные файлы; изменение рецепта, числа генератора, размера,
оттенка или обработки создаёт другую папку. Изменённые файлы и папки от других параметров не перезаписываются.

## Заготовки и роли

| Роль стиля | Заготовки |
|---|---|
| `wall` | `concrete`, `brick`, `plaster`, `tiles`, `roof_tiles`, `corrugated_metal`, `glass_grime` |
| `ground` | `asphalt`, `grass`, `dirt`, `sand` |
| `prop` | `rusty_metal`, `painted_metal`, `wood_planks` |
| `interior` | `fabric`, `leather`, `rubber`, `plastic` |
| `decal` | `grime_overlay`, `decal_overlay` |

Дефисы и подчёркивания в именах заготовок взаимозаменяемы. Материалы роли `interior` намеренно тёмные:
они рассчитаны на обивку и отделку салонов. `glass_grime` и обе накладки сохраняют полупрозрачность в DXT3;
остальные заготовки используют DXT1.

## Как это работает

Авторские рецепты узлов в JSON не содержат игровых пикселей. Синус и косинус координат UV обеспечивают
периодичность шума по обеим осям; швы кирпича, гофры, доски и переплетение ткани задаются повторяющимися
узловыми рисунками. Cycles без окна запекает излучение плоскости в размере, вчетверо превышающем заданный,
на процессоре и с отдельным профилем. При необходимости второй проход запекает прозрачность. Установленный
аддон Blender и извлечение DragonFF не требуются.

Обработка уменьшает изображение усреднением, сглаживает его с учётом соседних повторов, добавляет зерно двух
масштабов и подгоняет цвет и яркость под числовые распределения оригинальной игры, включённые в рецепты.
Это выборки `style.texture` для чистой версии PC 1.0 US: по 160 текстур стен, земли и предметов, 84 текстуры
салонов и 45 наклеек. Для генерации индекс не нужен. И PNG, и результат настоящего сжатия и декодирования DXT
должны получить оценку `in` от той же проверки, что использует [style.texture](style.md); нарушение даёт
`CHECK_FAILED`, а не успешный результат. Оценка `in` допускает отдельные показатели у границы распределения;
возвращаемые строки показывают их значения.

В каждой папке находятся PNG материала, `preview/<preset>.png`, `texmod.json` и `texlib.json`. Описание <!-- linkcheck: ignore -->
упаковки включает только материал, формат DXT1/DXT3 и один уровень для салонов либо полную цепочку уровней
для поверхностей мира. Передайте возвращённую папку в [texture.pack](texmod.md); вложенная папка образцов
не упаковывается. Метаданные сохраняют хеши файлов, показатели стиля и время запекания и процесса. Повторяемость
обеспечивается при той же версии Blender и обработки. Промежуточные файлы идут во временную папку процесса.

## Ссылки на оригинальные текстуры и потоковая загрузка

Поиск использует активные текстуры, на которые действительно ссылаются оригинальные модели `objs`/`tobj`.
Роль определяется приблизительно по имени, цвет — по усреднённым опорным цветам DXT из индекса, без
декодирования пикселей. Полноразмерные текстуры идут перед маленькими текстурами дальних моделей.
Результат содержит `id` текстуры, `ide_txd`, `texture_name`, `material_preset`, размер, цвет, число моделей карты
и пример модели. Для перехода по страницам используйте `limit` и возвращённый `cursor`. Цвет можно написать
в самом запросе, например `red brick`.

Запишите имя текстуры в материал DFF, а имя TXD — в поле словаря текстур объекта в IDE, без расширения `.txd`.
Оригинальный TXD и его родители `txdp` должны оставаться в зарегистрированных архивах и загружаться движком
вместе с моделью. Совпадающее имя или соседний объект не удерживают TXD в памяти. Замена одного DFF сохраняет
старое поле TXD в IDE. Не включайте оригинальные пиксели в пакет мода.

Такое использование предназначено **только для объектов карты**, не для машин, деталей тюнинга, персонажей
или оружия. У модели одно поле TXD в IDE: все материалы должны находиться в этом словаре или его родителях.
Для несвязанных словарей либо сочетания собственных упакованных картинок с оригинальными ссылками нужны
отдельные объекты.

## Интерфейс Python и дальнейшее подключение к kit

```python
from satk.texlib.vanilla import material_preset, export_plan

material = material_preset("vanilla:chicano10_lae/brickred", asset_class="map")
plan = export_plan([material["vanilla"]], asset_class="map", own_textures=[])
```

Вспомогательная функция проверяет наличие текстуры и её использование на карте, отклоняет неподходящие
классы, проверяет родителей и перекрытие имён, возвращая имя словаря для IDE без извлечения и записи файлов.
`material_preset` возвращает совместимое с kit описание с `shared=True`. Функция GPL
`satk_blender.texlib.materials.apply_reference` применяет его к материалу Blender с искусственной заглушкой
и записывает `satk_vanilla`.

Текущий экспортёр kit **ещё не обрабатывает** эти заготовки. Для подключения нужно:

1. Направить имена материалов с `vanilla:` в `apply_reference` и сохранять ссылку `satk_vanilla` каждого материала.
2. Собрать ссылки в описание экспорта Blender и вызвать `export_plan` перед упаковкой.
3. При `reference_only=True` пропустить упаковку TXD, включая пустой словарь, записать `ide_txd` в определение
   объекта карты в IDE и передавать эту ссылку в упаковку добавляемого объекта вместо нового файла TXD.

Эти изменения относятся к kit и его интеграции с упаковкой. Пока они не подключены, используйте функцию для
подготовки ссылки и соответствующего определения IDE; одного `kit.export` для этого недостаточно.
