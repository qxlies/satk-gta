# Модели: превью без GPU и экспорт в glTF, OBJ и «как в игре»

[English version](../en/models.md)

Пакет: `satk.model3d`.

## Что это

Показывает модель игры картинкой и выгружает её в форматы, которые открывают Blender и любые 3D-просмотрщики.
Превью рисует собственный программный растеризатор satk (`soft`, numpy): без видеокарты, окна и вьювера, побайтно
одинаково при повторе. Поэтому миниатюры **всех** моделей игры получаются за минуты. DFF, TXD и COL читаются из
IMG-архивов только на чтение (через индекс ассетов `satk.index`). Всё пишется под `<work>`: превью — в
`<work>/cache/model/`, экспорт — в `<work>/out/models/<имя>/`, файлы «как в игре» — в `<work>/cache/raw/<профиль>/`.

## Быстрый пример

```powershell
satk model image model:411
satk model image lae2_roads89 --views 1 --size 256
satk asset export model:411 --format glb
satk asset export model:411 --format raw
```

Что вернётся (сокращённо):

```json
{"ok":true,"id":"model:411","file":"<work>/cache/model/de2d9659f2e6-a8a588ec0813-soft-4-384.png",
 "backend":"soft","name":"infernus","w":768,"h":768,
 "legend":[[1,45.0,25.0],[2,135.0,25.0],[3,225.0,25.0],[4,315.0,25.0]],
 "stats":{"tris":3072,"drawn":3222,"tex_missing":0,"cover":[0.262,0.251,0.251,0.262]},"cached":false}
{"ok":true,"id":"model:411","name":"infernus","format":"glb","dir":"<work>/out/models/infernus",
 "files":["<work>/out/models/infernus/infernus.glb"],
 "stats":{"tris":3072,"verts":3573,"meshes":15,"materials":19,"textures":13,"tex_missing":0}}
```

`legend` — номер ячейки листа (слева направо, сверху вниз), азимут и возвышение камеры в градусах;
`cover` — доля пикселей модели в каждом ракурсе (близко к 0 — модель почти не видна).

## Команды

| Команда | MCP | Что делает |
|---|---|---|
| `satk model image ID [--views 4] [--size 384] [--backend auto\|soft\|ariane\|blender] [--force]` | `model_image` | превью: `views` ракурсов вокруг модели, лист 2×2 для 4 ракурсов (768×768 при `--size 384`) |
| `satk model image --all --size 128 --views 1 [--jobs 12] [--force]` | `model_image` (`all`; долгая операция) | миниатюры всех моделей с DFF; уже готовые пропускаются; манифест `<work>/out/models/thumbs-<профиль>-<size>x<views>.json` |
| `satk asset export ID --format glb\|obj\|png\|raw [--out DIR]` | `asset_export` | экспорт модели; `png` — её текстуры, `raw` — DFF + цепочка TXD + COL как в игре |

`ID` — `model:411`, `model:infernus`, просто `411` или `infernus`, `dff:infernus` (модель с этим именем DFF) или
`inst:lae2_stream0#4` (модель этой расстановки). У всех команд есть `--profile` (по умолчанию `vanilla`).
`--out` допускается только внутри `<work>`.

## Как это устроено

**Превью `soft`.**
- Камера на сфере вокруг модели: при азимуте 0 камера стоит на +Y и смотрит на −Y (перед машины); азимут растёт
  против часовой стрелки, если смотреть сверху. Четыре ракурса — 45/135/225/315° при возвышении 25°. Каждый
  ракурс кадрируется по модели с полем 5 %.
- Цвет = текстура (ближайший тексель, уровень мипа по размеру треугольника на экране) × цвет материала ×
  prelit-цвет вершин. Поверх — мягкий двусторонний «фонарь» от камеры; модели без prelit (машины, педы) получают
  фоновый и диффузный свет.
- Альфа: текстуры с альфой отсекаются по 0,5; полупрозрачный цвет материала (стёкла машин) смешивается одним
  слоем поверх ближайшей непрозрачной поверхности.
- До 256 px на ракурс используется суперсэмплинг 2×. Фон — `#b2bac4`.
- Как в игре: у машин скрыты `*_dam` и `*_vlo`, колесо `wheel` размножено по пустым кадрам `wheel_??_dummy`,
  цветовые ключи покраски заменены первой парой цветов из `data\carcols.dat`, ключи фар — белым и красным. Педы
  (скин, кость `Pelvis`) поставлены вертикально лицом к +Y.
- Модель без DFF (например, `model:300` `cutobj01`, `hier`) даёт серую заглушку и предупреждение `NO_DFF`,
  а не ошибку.

**Кэш.** `<work>/cache/model/<хэш DFF>-<хэш цепочки TXD и настроек>-<backend>-<views>-<size>.png` и рядом `.json`
со статистикой. Повтор отдаёт готовый файл (`"cached":true`), `--force` перерисовывает (байты те же). Версия
растеризатора входит в хэш, поэтому после изменения алгоритма кэш обновится сам.

**Бэкенды.** `auto` = `soft`. `ariane` — запущенный вьювер (`satk view start`), метод SAAP `asset.render`,
по ракурсу на вызов. `blender` — раннер Blender ([blender.md](blender.md), `import_model` с рендером, 1 или
4 ракурса). Если бэкенд не запущен или не смог нарисовать, превью рисует `soft`, а в `warn` попадает
`FALLBACK: backend ariane failed (...)`.

**Экспорт.**
- `glb` — glTF 2.0 одним файлом, писатель без зависимостей. Узел `satk_root` переводит Z-up игры в Y-up glTF;
  ниже — узлы кадров DFF с локальными матрицами и меши: `POSITION`, `NORMAL` (пересчитываются, если в DFF их
  нет), `TEXCOORD_0/1`, `COLOR_0` = prelit (день), `COLOR_1` = ночные цвета. Текстуры — встроенные PNG;
  `alphaMode` — `MASK` для текстур с альфой и `BLEND` для полупрозрачного цвета. Состояния `*_dam`/`*_vlo`
  сохраняются с `extras.satk_state`.
- `obj` — OBJ + MTL + PNG рядом. Тоже Y-up (импорт Blender по умолчанию ставит модель правильно), матрицы
  кадров «запечены», `vt` с началом внизу.
- `png` — все найденные текстуры модели в PNG (RGBA).
- `raw` — DFF и TXD отдельными файлами (без добивки IMG до сектора) и `.col`-архив модели; у машин коллизия
  остаётся встроенной в DFF. Для DragonFF и Blender.
- Экспорт не добавляет копий колёс и не прячет детали: в файле ровно то, что в DFF (у `model:411`
  3 072 треугольника).

**Миниатюры всех моделей** (`--all`). Модели сортируются по TXD и делятся на пачки по процессам (`--jobs`,
по умолчанию 12), поэтому общий TXD (`vehicle` и т. п.) декодируется один раз на процесс. Ошибки отдельных
моделей не останавливают прогон: они перечислены в ответе (`errors`, первые 50) и в манифесте.

## Ограничения и известные проблемы

- Освещение условное (без теней, отражений и ночного режима); для «красивого» кадра — `--backend blender`.
- Анимации не применяются: педы и `anim`-объекты остаются в позе из DFF.
- `--backend ariane` рисует по одному ракурсу за вызов; машины и педы вьювер может не загрузить — тогда
  срабатывает откат на `soft`.
- `--backend blender` рисует 1 или 4 ракурса (другое число — откат на `soft`); возвышение у него всегда 25°,
  а азимут он отсчитывает по-своему.
- Файлы модели берутся из индекса (`satk.index`); без него команды отвечают `INDEX_MISSING`
  (`satk index build`). Решения — в [troubleshooting.md](troubleshooting.md).

## Python-API (если другие пакеты его используют)

```python
from satk.model3d import api
api.image("model:411", views=4, size=384)            # конверт: file, backend, legend, stats
api.export("model:411", "glb")                        # конверт: files, stats
from satk.model3d.batch import thumbnails
thumbnails(size=128, views=1, jobs=12)                # миниатюры всех моделей
```
