# `satk texture` и `satk map`: текстуры, контакт-листы, карта сверху

[English version](../en/media.md)

Пакет: `satk.media`.

## Что это

Картинки для человека и агента из индекса ассетов (`satk.index`) и файлов игры: PNG отдельных текстур,
пронумерованные контакт-листы («одна картинка вместо N») и карта района сверху с номерами объектов. Игровые файлы
открываются только на чтение, всё пишется под `<work>`: кэш текстур — в `<work>/cache/tex/`, листы — в
`<work>/out/sheets/`, карты — в `<work>/out/maps/`. Ответ содержит **пути** к PNG и JSON-легенду; подписи агент
читает из легенды, а не с картинки.

## Быстрый пример

```powershell
satk texture image tex:bistro/vent_64
satk texture image txd:lawest1 --mode sheet
satk map image --center 2495,-1687 --span 300
```

Что вернётся (сокращённо):

```json
{"ok":true,"files":["<work>/cache/tex/6e/6e63ecc6dc8ee4ad8bfd1139.png"],"legend":[[1,"tex:bistro/vent_64","64x64 X8R8G8B8"]]}
{"ok":true,"files":["<work>/out/sheets/txd_lawest1-e08191d440c08b7a.png"],"legend":[[1,"tex:lawest1/newtreeleaves128","128x128 DXT3"],["…"]]}
{"ok":true,"file":"<work>/out/maps/map_2495_m1687_300m_768_….png","legend":[[1,"inst:lae2_stream0#92","stormd_fillb"],["…"]],"m_per_px":0.3906,"view":[2345.0,-1837.0,2645.0,-1537.0],"counts":{"inst":397,"lod":0,"zone":0}}
```

## Команды

| Команда | MCP | Что делает |
|---|---|---|
| `satk texture image SID... [--mode png\|sheet] [--size N] [--labels]` | `texture_image` | PNG текстур (`tex:`/`pix:`; `txd:` и `model:` раскрываются во все свои текстуры) или контакт-листы; `files` + `legend [n, sid, "WxH FMT"]` |
| `satk texture export-all [--jobs 12]` | — (через `satk_op`; долгая операция) | mip 0 всех уникальных текстур профиля в кэш (14 560 в `vanilla`); уже готовые пропускаются |
| `satk map image --center X,Y [--span 300] [--px 768] [--layers inst,lod,zone] [--area 0] [--labels 20]` | `map_image` (`x`, `y`) | карта сверху; `file`, `legend [n, sid, name]`, `m_per_px`, `view`, `counts` |

У всех команд есть `--profile` (по умолчанию `vanilla`).

Параметры:

- `--size`: в режиме `png` — длинная сторона (по умолчанию 256, `0` — оригинал; мелкие текстуры не
  увеличиваются); в режиме `sheet` — размер ячейки (по умолчанию 128).
- Лист — до 8×8 ячеек; больше 64 текстур раскладываются на несколько листов (`warn: PAGES`), не больше 4
  (сверх этого — `warn: TRUNCATED`). В режиме `png` за один вызов пишется не больше 64 файлов (`warn: TRUNCATED`).
- `--layers` (по умолчанию `inst`): `inst` — HD-расстановки (улица оранжевым, интерьеры фиолетовым), `lod` — LOD
  синим, `zone` — прямоугольники зон с именами (в ответе `zones` — зоны, в которых лежит центр).
- `--area -1` — все интерьеры сразу; `--labels 0` — без номеров.
- MCP: `inline=true` прикладывает картинку к ответу (не больше 1024 px); по умолчанию возвращается только путь.

## Как это устроено

- **Кэш по содержимому.** Путь PNG выводится из хэша пикселей: `<work>/cache/tex/<hh>/<pix>.png` (mip 0) и
  `<pix>@<size>.png` (уменьшенная копия). Одинаковые пиксели из разных TXD — один файл; готовый файл не
  пересчитывается и не переписывается. Листы и карты тоже адресуются ключом запроса (карта — ещё и `content_hash`
  индекса), поэтому повтор возвращает готовый файл.
- **Декодирование:** `satk.formats.dxt.decode_rgba` (Pillow `bcn` → numpy → чистый Python). Смещения mip 0
  берутся из индекса (`TexRef`), TXD заново не разбирается. DXT1 с растром 565 непрозрачна; PAL8 (`outro`) идёт
  через палитру. Полностью непрозрачные картинки сохраняются в RGB.
- **PNG:** Pillow, а без него — `zlib` из стандартной библиотеки (`SATK_MEDIA_NO_PILLOW=1` включает этот путь
  принудительно). Пиксели в обоих случаях одинаковые; метаданных (времени и т. п.) в файлах нет.
- **Номера и подписи** рисуются встроенным растровым шрифтом 5×7: результат одинаков на любой машине и не зависит
  от шрифтов Pillow. Номер ячейки — белые цифры на чёрной плашке с жёлтой рамкой в левом верхнем углу; прозрачные
  текстуры лежат на сером шахматном фоне, мелкие увеличены в целое число раз.
- **Карта:** отпечатки — мировые AABB расстановок из индекса (поворот уже учтён), север сверху, сетка в мировых
  координатах, масштабная линейка. Номера получают самые крупные видимые объекты; очень большие (дороги, земля —
  больше 15 % кадра) идут последними, номера не налезают друг на друга.
- **Скорость** на машине автора (12 процессов, Pillow): `export-all` по ванили — 17,5 с на 14 560 текстур
  (около 420 МБ PNG), повтор — 0,9 с; без Pillow (numpy + zlib) — 19,5 с. Карта 300 м — 0,04–0,3 с, лист из
  15 текстур — 0,03 с.

## Ограничения и известные проблемы

- Нужен собранный индекс профиля: без него команды отвечают `INDEX_MISSING` (код выхода 3) с подсказкой
  `satk index build`.
- Отпечатки на карте — прямоугольники по осям, а не повёрнутые контуры моделей; рельефа и воды на карте нет.
- Текстуры консольных платформ (не 8/9) пикселей не имеют: `UNSUPPORTED`, на листе — красная рамка и пометка
  в легенде. Решения других проблем — в [troubleshooting.md](troubleshooting.md).

## Python-API (если другие пакеты его используют)

```python
from satk.media import texture_png, contact_sheet, map_image, export_all

png = texture_png("tex:bistro/vent_64", size=256)                     # Path
sheet, legend = contact_sheet(["txd:lawest1"], cols=0)                 # cols=0 — автоматически (до 8)
mp, legend, m_per_px = map_image(2495, -1687, span=300, layers=("inst", "zone"))
stats = export_all(jobs=12)                                            # {"written", "skipped", "seconds", "backend", ...}
```

Низкоуровневое: `satk.media.texture.resolve_refs(db, sids)`, `decode_ref(TexRef)`, `png_for_ref(TexRef, size)`;
`satk.media.sheet.render_sheet(refs, ...)`; `satk.media.mapplot.render_map(...)` (полный ответ `map_image`).
